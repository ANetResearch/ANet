# 发行版设计:按需求裁剪的 anet daemon

**状态:设计稿,未发布。** 本文整理可能的交付形态与对应的用户场景,供讨论;
不代表已经决定要发布这些组合。

## 先看数据

裁剪的直觉理由通常是"体积"。实测结果不支持这个理由:

(下列数字重测于 2026-09-03,go 1.26,`-trimpath -ldflags "-s -w"`。)

| 构建 | 体积 | 省下 |
| --- | --- | --- |
| 默认(不含 shell) | 14,320 K | — |
| 去掉全部九个减法模块 | 12,096 K | 15% |

单独去掉每个模块:

| tag | 省下 | 占可省总量 |
| --- | --- | --- |
| `no_mcp` | 1,900 K | **85%** |
| `no_x402` | 124 K | 5% |
| `no_cas` | 60 K | 2% |
| `no_blackboard` | 44 K | 1% |
| `no_org` | 32 K | 1% |
| `no_p2p` | 28 K | 1% |
| `no_taskboard` | 24 K | 1% |
| `no_anetlink` | 20 K | <1% |
| `no_service` | 16 K | <1% |

加法 tag 反过来算 —— 加进去多少:

| tag | 加上 |
| --- | --- |
| `shell` | 28 K |

**结论:除 MCP 外,没有一个模块对体积有实质影响。** 剩下的 17.6 MB 是 Go 运行时、
`net/http`、加密库和 SQLite 驱动,与模块无关。

依赖数同理:默认构建链接 307 个包,`no_mcp` 降到 273(MCP SDK 及其 jsonschema 依赖),
九个减法 tag 全用上降到 264。`-tags shell` 加 1 个。

所以**按体积分发行版是站不住的**。真正值得分的维度有三个:

1. **攻击面** —— 这个构建会打开什么、接受什么
2. **可被要求做什么** —— 一个没有付费模块的节点不可能被诱导付款
3. **运维复杂度** —— 要配几个块、有几种失败模式

## 攻击面:每个模块带来什么

| 模块 | 打开的入口 | 出站行为 |
| --- | --- | --- |
| `x402` | **公开 HTTP 监听口**(配了 `voucher_addr` 时) | 向 hub 发结算、拉发放链 |
| `p2p` | **入站对等连接** | 主动连对等节点 |
| `mcp` | stdio 服务(由本机进程启动) | 无 |
| `service` | 无 | 向本机 HTTP 服务发请求 |
| `anetlink` | 无 | 连 ANetLink 的 unix socket |
| `cas` / `blackboard` / `org` | 无 | 无 |
| `shell` | 无(经 hub 或 p2p 到达) | **在宿主机上执行命令** |

只有 `x402` 和 `p2p` 会让节点**接受外部连接**。这是分发行版最实在的一条线。

`shell` 不开端口,但它是唯一一个把网络请求变成本机命令执行的模块,因此单独占一条线:
它是本文里唯一用**加法 tag** 的模块,默认构建不含它。见 [SHELL-zh.md](SHELL-zh.md)。

## 六种交付形态,外加一条正交的开关

### 1 · `anet-min` —— 只是接入

```
-tags no_x402,no_service,no_mcp,no_cas,no_org,no_blackboard,no_p2p,no_anetlink
```

**给谁**:只想让自己的 agent 接入网络、找人、委派任务的用户。不提供服务、不收钱、
不参与共脑。

**能做**:注册到 hub、`find`、`delegate`、收结果、验收据、评价。证据链完整。

**不能做**:被别人调用能力、收付费用、点对点。

**姿态**:不监听任何公开端口,只有回环控制面。出站只连它注册的那个 hub。
这是攻击面最小的形态,也是"我只是想用"的默认答案。

体积 17.6 MB。

### 2 · `anet-standard` —— 接入 + 提供服务

```
-tags no_x402,no_mcp,no_cas,no_org,no_blackboard,no_p2p,no_anetlink
```
(即保留 `service`)

**给谁**:把自己已有的 HTTP 服务挂上网络,等别人调用。

**能做**:1 的全部,加上以能力 id 对外提供服务、签发收据、上证据链。

**不能做**:收费。标价的能力在这个构建上会答 `UNAVAILABLE` 并说明原因 ——
**不会免费替人干活**。

**姿态**:仍不监听公开端口(调用经 hub 中继进来)。出站多了本机服务。

### 3 · `anet-paid` —— 接入 + 服务 + 收费

```
-tags no_mcp,no_cas,no_org,no_blackboard,no_p2p,no_anetlink
```
(保留 `service` + `x402`)

**给谁**:要靠提供能力赚 credit 的用户。

**能做**:2 的全部,加上标价、报价、结算、开凭证、兑付、审计 hub 的发放链、对账。

**姿态**:**如果配了 `voucher_addr` 会打开一个公开监听口**。不配就不开 ——
凭证兑付是可选的,不用网关也能经中继收费。

这是需要运维认真读文档的第一档:公开端口、余额托管在 hub、跨 hub 结算的信任边界。

### 4 · `anet-agent` —— 给 AI 编码助手用

```
-tags no_x402,no_cas,no_org,no_blackboard,no_p2p,no_anetlink
```
(保留 `service` + `mcp`)

**给谁**:Claude Code / Cursor 之类的用户,想让助手自己会找 agent、会委派。

**能做**:2 的全部,加上 MCP stdio 服务(9 个工具)。

**代价**:体积 +2.8 MB,依赖 +29 个包。这是唯一一个体积理由成立的模块。

**姿态**:MCP 服务由本机进程通过 stdio 启动,不监听网络。

### 5 · `anet-p2p` —— 不想经过 hub

```
-tags no_x402,no_mcp,no_cas,no_org,no_blackboard,no_anetlink
```
(保留 `service` + `p2p`)

**给谁**:同一内网/可直连的一组节点,不希望委派经过第三方服务器。

**能做**:2 的全部,加上直连投递。hub 仍然需要用于**发现**和**密钥历史**
—— 纯 p2p 无发现是做不到的,这一点要在文档里写清楚,不能让人以为可以完全脱离 hub。

**姿态**:接受入站对等连接。

**会合点**:`anetpeer --rendezvous` 接受 hub 地址或本地目录。目录形式要求两端共享
文件系统,因此只能覆盖同一台机器上的节点 —— 而这恰好是不需要 p2p 的情况。用 hub
时,节点用 `anet p2p-advertise <addr>` 发布自己的直连地址(签名的自述,与 hub-leave
同族),对端用 `GET /agents/{aid}/p2p` 查询。发布是自愿的:不发布就不在目录里,
仍然经 hub 收活。

代价要说清楚:hub 因此持有一份地址表。所以目录本身通过 `GET /p2p/peers` 公开 ——
付出这个代价的人能看见它到底装了什么。载荷、证据、结果都不经过 hub,hub 知道的是
"两个节点互相查过地址",不知道它们之后做了什么。

**未决**:一个"注册到 hub 只为发现、投递全走 p2p"的模式目前没有开关,
现在是"能直连就直连,不能就走 hub"的自动回退。要不要做成可强制,待定。

### 6 · `anet-full` —— 全部

**给谁**:开发、联调、演示;以及确实需要共脑或组织能力的部署。

**能做**:全部,含 `blackboard`(共脑)、`org`(组织成员凭证)、`cas`(内容寻址存储)、
`anetlink`(设备能力)。

**姿态**:三个模块里 `blackboard` / `org` / `cas` 都不开端口,加进来主要是功能而非风险。

### 正交项 · `+shell` —— 允许远程执行本机命令

```
-tags shell[,<上面任意一档的减法 tag>]
```

不是第七种形态,是加在任意一档上的一个开关,所以每一档都有一对孪生版:
**同一档、同一 commit,一个能在宿主机上执行命令,一个连这段代码都没有。**

**给谁**:有多台机器(开发板、测试机、边缘节点)需要从网络另一端触发重启服务、
读日志、烧固件并拿到回显的用户。

**为什么是加法 tag**:其余模块默认在、`no_<name>` 去掉;这个默认不在,`-tags shell`
才有。两种 tag 写错的代价不对称 —— 减法 tag 漏了,是某人想去掉的模块没去掉;
加法 tag 漏了,是命令执行能力进了所有没要过它的构建。

**姿态**:不开端口(请求经 hub 或 p2p 到达),不提权(以 daemon 自己的用户身份运行)。
带 tag 的构建在没有 `modules.shell` 配置块时不注册任何能力;配了但名单为空时拒绝所有
远程调用。收权走 `allow_file`,每次调用重读,不需重启。配置与行为约定见
[SHELL-zh.md](SHELL-zh.md)。

**发行建议**:先只发 `standard` 与 `agent` 两档的孪生版,不发 `full+shell` ——
`full` 已经带 p2p 的入站连接,再叠上命令执行,是本套件里姿态最开的组合,应当由
部署方自己构建而不是由我们默认提供。

## 实测(每个形态都编译并符号级验证过)

| 形态 | 体积 | 依赖包数 | 二进制里实际有的模块 |
| --- | --- | --- | --- |
| min | 12,132 K | 265 | (无) |
| standard | 12,144 K | 266 | service |
| paid | 12,264 K | 267 | service x402 |
| agent | 14,044 K | 300 | service mcp |
| p2p | 12,172 K | 267 | service p2p |
| full | 14,320 K | 307 | 全部减法模块 |
| standard+shell | 12,192 K | 267 | service shell |
| agent+shell | 14,072 K | 301 | service mcp shell |
| full+shell | 14,348 K | 308 | 全部 |

`min` 到 `paid` 之间只差 132 K 和 2 个依赖 —— 再次说明分档的理由不是体积。
`agent` 比 `standard` 多 1.9 MB 和 34 个依赖,是唯一一个体积和依赖都跳一档的。
`+shell` 在任何一档上都只加 28 K 和 1 个依赖 —— 它值得单独一个 tag 的理由与体积无关,
是它能做什么。

## 组合矩阵

| 形态 | service | x402 | mcp | p2p | cas | blackboard | org | anetlink | shell | 公开端口 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| min | | | | | | | | | | 无 |
| standard | ✓ | | | | | | | | | 无 |
| paid | ✓ | ✓ | | | | | | | | 可选 |
| agent | ✓ | | ✓ | | | | | | | 无 |
| p2p | ✓ | | | ✓ | | | | | | **有** |
| full | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | | 可选 + 有 |
| 任意一档 `+shell` | | | | | | | | | **✓** | 不变 |

`shell` 一列在所有默认形态里都是空的,包括 `full`。这是加法 tag 的全部意义:
不写 `-tags shell` 就没有,`full` 也不例外。

## 这些说法是怎么验证的

`scripts/onboard.sh` 走一遍新用户从零到能用的完整路径,并在**每一档上**核对本文
对该档的说法:

- 三档各自构建成功,体积如上表
- 首次启动自动生成自证身份与控制令牌,报得出自己的构建 commit
- 加入 hub 之后,陌生人能取到它的密钥历史自行验签
- `min` 调用 `standard` 的免费能力成功,证据随结果返回
- **`min` 遇到标价的能力时,提供方答 `UNAVAILABLE` 并说明原因,不会白干**
- **`min` 的 `/balance`、`/redeem`、`/reconcile`、`/audit-hub` 都明确回答本构建没有付费支持**
- `paid` 读得到余额、能发起要价

24 项,全过。文档里的行为承诺不是描述,是被跑过的。

## 待决问题

**一、发几个?**

六种是分析出来的,不是需求验证过的。发得越多,组合测试面越大 ——
现在 CI 跑 10 种 tag 组合,六个发行版意味着六条要长期维护的分发线。

保守方案:先发 `min` / `standard` / `full` 三种,`paid` 和 `agent` 作为
`standard` 加一个 tag 的文档说明,不单独出包。

**二、怎么让用户选?**

按 tag 组合让用户自己拼,门槛太高。可能的做法:
- 安装脚本问几个问题("你要提供服务吗?要收费吗?"),再选构建
- 或者只发一个完整版,把裁剪留给自建的人

第二种更省事,但放弃了"不想要的功能就没有"这条承诺 —— 而这条承诺是
`no_x402` 那种"这个节点不可能被诱导付款"性质的来源。

**三、模块能不能运行时确认?**

现在 `anet status` 会列出编译进来的模块。一个用户拿到二进制,应该能一眼看出
它是哪一档。当前是可以的,但没有对应的发行版名字 —— 加一个 `anet version --profile`
之类,报"这是 standard 档"会更直接。

**四、`anet-min` 是不是真的够小?**

17.6 MB 对于"只是想接入"仍然偏大。如果这是个真问题,方向是减 SQLite 或换
更小的存储,而不是继续裁模块 —— 模块已经没有可裁的了。这需要先确认有没有人
真的在意。

## 不打算做的

- **按体积分档**。数据不支持,除 MCP 外每个模块都在百 K 以内。
- **运行时开关代替编译期裁剪**。"关掉了"和"不在二进制里"是两种性质,
  后者是 `no_x402` 这类承诺的全部内容。
