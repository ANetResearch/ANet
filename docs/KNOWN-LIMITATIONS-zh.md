# anet 已知局限

[English](KNOWN-LIMITATIONS.md)

本文列出 anet 0.2(daemon 之间端到端加密、对齐 A2A 的版本)已知的局限:哪些信息仍然对 hub 或别人可见,哪些防护有边界,哪些这一版没有做。写出来,是因为"不知道"和"知道没问题"是两回事 —— 把什么交给这张网络,应当在知情的前提下决定。

**适用范围**:anet ≥ 0.2.0,连接 wire 2 的 hub。0.1.x 的情况更弱:hub 以明文中继任务合同、聊天消息与结果,能读到全部任务内容;签名只能让双方识破伪造,挡不住 hub 读。

第 1–27 条与设计文档 [A2A-DESIGN-zh.md](A2A-DESIGN-zh.md) §21 一一对应,文末另列几条同样需要知道的事项。

---

## 1. hub 知道谁在什么时候给谁发了多大的消息

消息内容是加密的,hub 读不到;但在你发送的那一刻,hub 知道:

- **发送方**:往 hub 投递要以你的身份签名认证,hub 据此按发送方限流。hub 不把发送方写进中继存储,hub 进程也不逐条记录中继,但发送时刻它是知道的。
- **收件方**、**时间**、**大小**:大小按 Padmé 规则取整,只暴露量级,不暴露精确字节数。
- **来源 IP**。

**hub 前面的反向代理。** hub 的请求行多数带 AID(`/agents/<aid>/…`、`/a2a/v1/agents/<aid>/card`、`/fed/v2/keys/<aid>`),且来自客户端地址。保留访问日志的代理会把它们连同时间与响应大小写到 hub 主机的磁盘上,足以在 hub 删掉消息之后重建谁在何时与谁通信、多大。随 hub 下发的代理配置(ANetHub `deploy/nginx-hub.conf` 与 `nginx-hub.conf.example`)因此不保留 hub 的访问日志,错误日志只记 `crit` 级(更低级别的行带客户端地址与请求行),由主机 logrotate 轮转,按 Debian/Ubuntu 默认至多保留 14 天。运营者改用别的配置,就可能保留这类日志。你的 daemon 在给对端写之前查对端的加密公钥、卡片与验卡用的 KEL(A2A 客户端经 daemon 与对端通信时先取的代理卡片即由此而来),都把对端 AID 放在请求体里(`POST /agents/keys:lookup`、`/a2a/v1/agents/card:lookup`、`/agents/kel:lookup`),这些查询的请求行不含对端;p2p 地址查询(p2p 开启时 `anetpeer` 发出的 `GET /agents/{aid}/p2p`)与早于本版的 daemon 仍会在请求行里带对端 AID。

跨 hub 投递时,经手的对等 hub 同样看得到收件方与大小。连发送方也对 hub 隐藏(sealed sender)是后续工作,本版没有。

## 2. 前向保密以加密密钥的寿命为界

每个节点每 7 天换一把新的加密密钥,每把有效 14 天,私钥在失效后再保留 15 天(让在 hub 信箱里等了最长 14 天的消息仍能解开),之后删除。所以:一条消息在发出后**至多 29 天内**,如果有人既保存了它的密文(例如一个不守规矩的 hub 留了副本),又拿到了收件人的数据目录,就能把它解开;超过这个窗口,对应私钥已经删掉。

另外请注意:本机数据目录里保存的任务记录(`interactions.db`)本身不加密,拿到磁盘的人可以直接读到已经收下的任务。这一条讲的只是"经过网络的密文还能被解开多久"。

## 3. 大附件整条缓冲、一次加密

附件放在消息的密文里,整条消息一次加密(单次 AEAD),不分块。后果:收发两端都要把整条消息读进内存;传输中断要整条重发,没有断点续传;大小受限(单个附件 64 MiB,单条信封 96 MiB)。

## 4. 官方公共 agent 是任务的另一端,看得到调用内容

端到端加密保护的是传输途中,不对收件方保密。你调用官方公共 agent(如 `anet-echo-e`、`anet-tools`、`anet-docs`)时,它就是收件方,能看到你发去的参数和它返回的结果。调用任何其他 agent 也是一样:对方看得到你交给它的东西。

官方 agent 的保存策略(全文见 [deploy/official/README.md](../deploy/official/README.md) §5):

- **后端**不保存参数与结果,每次调用只在系统日志写一行元数据(时间、能力、状态、调用方 AID、交互 id、字节数、耗时)。
- **证据链**(永久、只追加)对公共能力的调用只记调用方、能力、状态、指标与结果的 CID(`"evidence": "cid"` 模式),不记参数和结果;对话消息只记 CID 与字节数,公共能力调用与陌生人的消息按 10 分钟窗口聚合计数。
- **交互库**保存签名请求(含参数)与结果,用于应答、重投与对账;调用结束 **7 天后**删除(每天清理一次,实际保存 7–8 天),删除计数记上证据链。

这是官方 agent 的配置,也是任何 anet 节点对公共能力的缺省做法:公共能力的证据缺省只记 CID,`public_cap` 交互 7 天后清理。节点运营者可以把某个公共能力的证据改为 `full`(连同后端的完整回复一起永久上链);你调用的是不是官方 agent、对方怎么配置,决定了对方保存什么。

## 5. 沙箱里的本地 agent 仍然可以联网

对不在信任名单里的对端,自动回复可以设为 `auto_reply.untrusted=sandbox`,在 bubblewrap 沙箱里运行本机编码 agent(仅 Linux)。沙箱把家目录、数据目录、控制令牌、运行时目录挡在外面,但**不隔离网络**:

- 沙箱里的 agent 仍可联网,可以把工作目录里的内容、或它自己的凭据(`auto_reply.api_key` 以环境变量传给它)发出去;
- 宿主机上监听回环地址的 TCP 服务、以及抽象命名空间的 Unix socket,在沙箱里仍然可达。所以回环服务不能靠"只监听 127.0.0.1"当作认证 —— 例如 `service` 模块的后端应当以每后端令牌认证 daemon。

沙箱不可用时按失败处理(不会退回到无沙箱运行)。网络隔离与非 Linux 沙箱本版没有做(见第 14 条)。

## 6. 对端身份是首次见面时信任的

第一次见到某个 AID 时,daemon 接受它自证明的密钥历史(KEL)。之后只接受这份历史的延伸,回退与分叉都会拒收 —— 但这项保护只覆盖本机已经有持久记录的对端。hub 可以向一个从没见过某 AID 的节点提供旧卡片或截断的 KEL,daemon 只能拒绝"回退到本机已见状态之前"。

实际含义:如果某个 agent 在私钥泄露后轮换过密钥,一个此前从没和它打过交道的节点,仍可能被 hub 喂一份轮换前的历史,从而接受用旧密钥签的消息。

## 7. `hub:<aid>` 网络名不符合 CAIP-2

付款对象里的网络名形如 `hub:<hub 的 AID>`,不满足 CAIP-2 的格式要求;严格校验 CAIP-2 的第三方工具会拒绝它。`anet-credit` scheme 文档写明了这一偏离。

## 8. 阻塞式 SendMessage 可能等很久,客户端超时不取消任务

经本机 A2A 接口用 `return_immediately=false` 发 SendMessage 时,daemon 会一直等到任务终态或需要输入才返回;对端离线时这可能很久。客户端自己超时**不会**取消任务,任务继续进行(在自动付款额度内可能已经付了款);客户端再重试,会建第二个任务。按 `(contextId, messageId)` 的去重对"每次调用都生成新 messageId"的客户端(例如 Hermes)不起作用。

找回之前的任务:按 contextId 调 ListTasks,或用 MCP `list_tasks` 的 `context_id` 过滤。

对这类客户端有一处宽松处理,偏离 A2A 规范:只带 contextId、不带 taskId 的消息,当该 context 下本节点发给该端点所代表 agent 的任务里恰有一个处于 `input-required` 时,续写这个任务而不新建(能力调用总是新建;等待中的能力调用只由付款消息续写)。没有或有多个这样的任务时,按规范新建任务。控制面与 MCP 不做这种宽松处理:请写明任务。

## 9. 付款与评价可以被关联,公开发放链显示金额与 AID,结算金额可指向所买能力

- hub 能按付款方、收款方与时间,把结算记录与公开评价关联起来。结算里的交互绑定值是单向哈希,hub 不存交互 id、也不能由它反推交互 id,但这挡不住按时间与双方身份的关联。
- 公开发放链显示每一笔跨 hub 付款、清算与兑付的金额、时间与 AID,任何人可读。
- 经 hub 网关购买的凭证与报价含能力 id 与收款方,hub 可见。
- 结算请求不带"买的是什么",但带收款方与准确金额。收款方在卡片上公开了每项能力的价格(缺省如此)时,由"收款方 + 金额"就能推出买的是哪项能力:hub 对每笔结算都能做到,跨 hub 付款则任何读公开发放链的人都能做到。几项能力同价时无法区分。不想这样,可在 `config.json` 的 `payments` 块设 `"publish_prices": false`:卡片不再列出每项能力的价格,价格只在端到端加密的报价里给出;代价是调用方事先看不到价格,hub 网关也无法出售你的能力。profile 里自己写的 `pricing` 文字若列了价格,同样公开。

## 10. 首次安装信任提供脚本的主机

用 `curl … | sh` 从 agentnetwork.org.cn 或某个 hub 的域名首次安装时,你信任的是提供这个脚本的主机(目前与官方 hub 在同一台机器上)。按某个 hub 的 `llms.txt` 行事的 agent,执行的是那个 hub 给出的指令。不想依赖主机的,可以先下载 `install.sh` 与签名,用 `ssh-keygen -Y verify` 对照发布公钥核验后再执行。安装之后,`anet update` 只依赖发布签名密钥,不再信任下载主机。

## 11. 密钥轮换没有产品入口,旧密钥消息只有 1 小时宽限

目前没有触发 KEL 轮换的命令。轮换投入使用后,轮换前签名、轮换时还在信箱里的消息,在默认 1 小时宽限(`rotation_grace`)内仍被接受;超过宽限仍未取走的会被拒收。

## 12. 缺省的 `A2A-Version` 按 1.0 处理

A2A 规范要求请求没带 `A2A-Version` 时按 0.3 处理;anet 的本机 A2A 接口按 1.0 处理,否则会拒掉不发这个头的客户端。显式给出非 1.x 的版本会得到 `VersionNotSupportedError`。

## 13. 终端确认只能约束"只经 MCP 或 A2A 接口行事"的 agent

`anet pay`、`anet peers allow`、`anet inbound approve`、修改支出上限这几件事,CLI 要求在终端(`/dev/tty`)上确认。但这个检查在 CLI 进程里做,对应的控制面路由凭控制令牌即可调用,daemon 无法区分调用是否经过终端。所以它只约束那些**只能**经 MCP 工具或本机 A2A 接口行事的 agent。

任何能以你的用户身份执行命令的 agent —— 包括 Claude Code 等编码工具的 Bash,不论有没有 TTY —— 都可以读取控制令牌直接调用这些路由,或者直接改 `peers.*`、`config.json` 再重启 daemon。在同一个系统用户之下,不存在比这更强的边界。

## 14. 这一版没有处理的事

| 事项 | 归属与现状 |
|---|---|
| ANetLink `c1.sock` 的权限与 `SO_PEERCRED` 校验、按调用方 AID 授权 | 跨仓,ANetLink 单独立项 |
| 联邦按收件人所在 hub 定向转发 | 目前按对等表顺序逐个尝试,功能正确;被尝试到的对等 hub 也会收到这封密文及其收件人 |
| 交互级临时密钥 | 未做(第 2 条的前向保密窗口因此以节点密钥寿命为界) |
| 大附件分块 | 未做(见第 3 条) |
| sealed sender(对 hub 隐藏发送方) | 未做(见第 1 条) |
| 发放链的隐私格式 | 未做;改格式需要版本化,单独立项(见第 9 条) |
| 沙箱网络隔离 | 未做(见第 5 条) |
| 非 Linux 平台的沙箱 | 未做;这些平台上 `untrusted=sandbox` 按"沙箱不可用"处理 |

## 15. 没有持久记录的对端,每条消息都按首次见面处理

第 6 条的回退防护只覆盖本机有持久记录的对端:允许名单与信任名单里的、本节点主动联系过的、经人工批准的。陌生人的 KEL 与加密公钥只放在有上限的内存缓存里,仅用于加密拒绝回复;调用公开能力的对端、以及 `open` 策略下发来任务的陌生人,只记在那一个任务里,任务结束后删除。

所以对这些对端,daemon 对每一条消息都重新接受信封里自带的 KEL。这份 KEL 在发送方签名的密文里,hub 改不了;但如果某个 AID 的旧签名密钥泄露、它已经轮换,持有旧钥的一方可以附上一份截断到轮换之前的 KEL 冒充它,本节点没有已见状态可比。公开能力调用与 `open` 策略下的陌生人任务,因此不能依赖对端的轮换历史。同理,这些对端的卡片高水位只在内存里,daemon 重启后 hub 可以再提供更旧的卡片。

## 16. 证据链通过校验,不代表末尾没被截掉,也不代表没有漏记

`anet verify --chain` 通过,说明每条记录都由该 KEL 的 AID 签名、id 可以重算、逐条链接回创世;不说明末尾没有被截掉 —— 提前结束的链仍是有效的链。只有用 `--head` 给出从别处得知的记录(见证、早先的导出)并且被找到,才能排除截尾。

另外,证据写在业务事务之后:两者之间进程崩溃,这条事件就丢了,也不留缺口记录。所以 `anet audit` 不能把"链上没有"当作"没发生"。

## 17. "官方"标注只按 AID,只来自随二进制内嵌的签名清单

`"anet.official": true` 只依据随二进制打包、由发布密钥签名的官方清单,按 AID 判定:

- 清单过期后不标任何人,直到升级到带新清单的版本;
- 没有单独的吊销通道,靠发布新版本与清单有效期;清单序号不防回退,防回退靠 `anet update` 拒绝降级;
- 标注只是标签,不给准入、信任、付款或通道。

发现结果里,只有卡片验证通过(`VERIFIED`)的条目内容来自 agent 自己的签名;`include_uncarded` 列出的无卡片条目(`NONE`)除 AID 外都是 hub 的陈述。

## 18. 网络卡片的撤回只随注册发出

节点不再有任何公开能力时,它的 A2A 网络卡片应当撤回。撤回只随注册请求发给 hub;那一刻 hub 不可达的话,撤回不单独重试,要等下一次注册(重启、再次 `anet hub-register`、或卡片内容变化)。在那之前,hub 与联邦对端继续列出旧卡片。

## 19. 与 A2A、a2a-x402 规范的其他偏离

除第 7、12 条外:

- 只带 contextId 的宽松续写(见第 8 条);
- 本机 A2A 接口不按卡片声明的输入类型检查 raw part 的 `mediaType`;
- `payment-verified` 在 anet 表示已经结算扣款,规范与官方参考实现表示"验过、尚未扣款";
- `x402.payment.required` 是 x402 v2 对象;只认规范示例里 v1 形状的客户端读不懂它,要经 anet daemon 签名付款。

## 20. 拒绝(deny)一个对端,不撤销已经付了款的工作

对端被移进 deny 名单时,它进行中的任务被取消;但已提交或已完成付款的任务照常完成并交付,只在 `anet.policy.changed` 事件的 `skipped_paid` 里列出。

## 21. 端到端加密只覆盖 daemon 与 daemon 之间

- **A2A 客户端一侧的留存**:经本机 A2A 接口接入的客户端自己保存什么,不在 anet 的保护范围内。例如 Hermes 会把每次往来以明文写进 `~/.hermes/a2a_conversations/` 与 `a2a_audit.jsonl`。端到端加密只覆盖 daemon 与 daemon 之间。
- **本机 A2A 令牌能做什么**:`<数据目录>/modules/a2a/a2a_token.txt` 授权本机作为请求方向远端 agent 发任务、读这些任务,以及在 agent 档上限内付款;拿不到别人发给你的任务。持有它的本机程序可以以你的身份向网络上的任何 agent 发任务,所以它保持 0600;`anet agents wire hermes --a2a` 把它写进 `~/.hermes/config.yaml`(同样 0600)。
- 提供侧后端同理:daemon 把入站任务转给你配置的本机 A2A 服务(例如 Hermes)之后,那个服务保存什么由它自己决定。

## 22. 拒收记录有上限:极端洪泛下,很晚才到的旧委派可能被静默丢弃

被拒的委派,daemon 会持久记下"已拒收",防止 hub 日后重放时按届时的策略被重新接受。这张表有上限:某个发送方 15 天内被拒超过 1024 次,或全节点被拒超过 10 万次(例如大量新 AID 的洪泛)时,被挤出的记录转为该发送方自己按发送时间的下限。此后,该发送方晚于这些拒收才到达、发送时间却更早的首次投递(例如在信箱里压了很久的委派)按拒收丢弃,且不回复。下限只作用于该发送方本身,别的发送方的拒收抬不动它。

下限表也有上限:15 天内有超过 10 万个不同发送方的拒收被挤出时,最早到期的下限被忘掉;对应发送方被挤出的拒收若再被重放,会按届时的策略重新判定。

## 23. 陌生人发往未知任务的消息,立即得到 TaskNotFound

与本节点没有持久记录、不在名单里、也没有本节点发出的往来的发送方,发往本节点不认识的任务的消息,不在信箱里等它的委派,立即得到 TaskNotFound。发送方的外发按任务顺序投递,后续消息只会排在已进信箱的委派之后;仍会得到 TaskNotFound 的只有一种情形:委派本身在本节点暂时失败(例如存储错误),而同一批里其后的消息先被处理了。

## 24. 文本任务的回执,覆盖的是提供方交付的对话记录

`anet.receipt_verified=verified` 表示 provider 的签名成立,且回执与本任务的交互、双方、本节点发出的请求(request CID)和收到的交付物字节一一对应;任一不符的结果会被丢弃。文本任务的回执覆盖的是 provider 交付的那份对话记录,其中"请求方说的话"是 provider 的记录,本节点不逐条比对自己的消息日志,所以 `verified` 不证明请求方说过记录里的话;要核对原话,以请求方自己的消息日志为准。

## 25. 只有自述(profile)、没有公开能力的 agent,在别的 hub 上看不到

联邦在 hub 之间搬运的是签名卡片等签名对象,profile 摘要不在其中。只靠 profile 上架、没有公开能力的节点,卡片里没有能力,会出现在它所注册的 hub 的目录里,但对端 hub 据此不列出它(`list_agents` 的 `include_uncarded` 跨 hub 也看不到它)。希望被别的 hub 上的 agent 发现,请发布公开能力。

## 26. 本机后端的核实:Linux 之外只核对 socket 路径,TCP 后端须与 daemon 同一用户

`service` 模块与 A2A 后端把令牌、调用参数或任务正文交给本机后端之前,先核实对端是运营者指定的那个进程。推荐的 Unix socket 后端(`unix:///路径`)按 socket 所在路径的属主与权限、socket 的属主核对,在 Linux 上还用 `SO_PEERCRED` 核对监听进程的用户;其他平台读不到这一项,只做路径与属主检查。

TCP 后端须在配置里显式写 `allow_tcp: true`;连接落在本机上时(回环地址,或本机自己的网卡地址),只有在 Linux 上、且监听者与 daemon 是同一个用户时才会发送,其他平台一律拒绝。所以只能监听 TCP 的第三方后端(例如 Hermes 默认的 `127.0.0.1:9900`)只能在 Linux 上、以 daemon 的用户运行。连到另一台主机的后端靠 TLS 认证。

没有配置 `expected_uid`/`expected_user` 时,daemon 信任的是 socket 所在的目录链:root、daemon 自己的用户、socket 的属主,以及配置的 `socket_group` 的成员,都能换上自己的后端。与 daemon 同一用户的进程本来就能读取令牌与配置(第 13 条)。自 0.2.1 起,可由 socket 属主或 daemon 用户的私有组(组名与用户名相同、是其主组、没有其他成员,按 `/etc/passwd`、`/etc/group` 判定)写的目录(Debian/Ubuntu 缺省的 0775)视同该用户独占;有人把别的账户加进这个组,之后 daemon 按组内有他人拒绝,但在那之前它和该用户一样能改动这些目录。

## 27. 15 分钟内对方什么都没回的任务判失败,哪怕对方只是慢

你发出的任务,委派送出后 15 分钟内(`config.json` 的 `no_response_after`)对方没有回任何状态、消息或结果,daemon 就把它判为 `failed`,`anet.reason=no_response`,效果按"不知道"报(`anet.effect_status=UNVERIFIED`)。这是为了不让任务永远停在 `submitted`:对方拒绝任务的通知有限速,超出的静默丢弃,你原本永远等不到回答。代价是 daemon 分不清"拒绝了但没说"与"只是慢":人工处理、迟迟没回的文本任务,0.2.0 版本对方执行中的长调用(0.2.1 起的对方开始执行时会先回 `working`),离线超过 15 分钟的 agent,也都会这样结束。之后到达的结果仍会验签并记录在这个任务上,但终态之后对方发来的追问与中间回复不会保存。需要长时间等待时,把 `no_response_after` 调大(如 `"24h"`),或设为 `"0"` 关闭。

## 另外需要知道的

- **去掉内容之后,hub 仍然持有或看得到的**:agent 自述(卡片、KEL、加密公钥、profile);其中 KEL 与加密公钥对所有对等 hub 按精确 AID 可查,与"只在本 hub 可见"的可见性设置无关。此外还有评价关系图(谁评价了谁)、p2p 地址、活跃度(最近何时取信)、付款元数据,以及第 9 条的公开发放链。
- **评价不含任务内容**:评价只带评分与不超过 280 字符的短评;hub 核验回执与评价的签名及二者的对应关系,但它看不到内容,所以回执的内容绑定对 hub 一律是 `UNVERIFIED`。hub 统计里的 `tasks_completed` 从 wire 2 起表示"经评价公开的有效回执数",会少于实际完成的任务数。
- **completed 不等于成功**:A2A 状态 `completed` 只说明任务走完了。能力调用的效果另看 `anet.effect_status`(`UNVERIFIED` 表示 daemon 无法判断效果是否真的发生),回执是否核验另看 `anet.receipt_verified`;两者都不会被并进 `completed`。
- **"效果未知"从拿到连接起算**:`service` 模块与 ANetLink shim 调用后端时(taskboard 模块写看板时同样),传输层一旦为这次请求拿到连接,之后的任何错误(超时、断连、写出请求途中出错)都报"效果未知"(`UNVERIFIED`,`anet.reason=timeout` / `connection_lost`),哪怕请求实际一个字节也没写出去(例如复用的长连接已被后端关闭);只有确定没发出的失败——拨号被拒、socket 不存在、路径或对端身份核验不过(第 26 条)、拿到连接之前截止时间已到——才报 `UNAVAILABLE`。宁可把没发生的报成"不知道",也不把可能发生的报成"没发生";请求方重试前先向对方核实。连本机 TCP 后端时每条新连接要读一遍内核套接字表,这段时间计入调用的截止时间(连接多、负载高的主机上可达数百毫秒):`timeout_ms` 设得很短时,调用可能在连接建好之前就到期,得到 `UNAVAILABLE`;Unix socket 后端只做几次 `lstat`,不受此影响。
- **被拒的对端能否察觉**:入站策略为 `closed` 时,名单里被拒绝(deny)的对端与陌生人得到同样的回复;但如果节点配置了公开能力,被拒绝的对端调用公开能力会被拒、陌生人却会被服务,对端可以由此察觉。`approve` 与 `open` 策略下,被拒绝的对端总能察觉。
- **导入身份时的加密密钥**:导入身份若不带加密密钥环,daemon 启动时会新建一把;此前发给旧密钥、仍在途中或在信箱里的消息将无法解开。
- **卡片签名里的 `jku`**:A2A 卡片签名头中的 JWKS 地址(`jku`)是 hub 的陈述,可信度低于 KEL;验证以 KEL 为准。
- **同机其他用户与本机 A2A 令牌**:anet 自己的客户端(CLI、`anet mcp`)在发送控制令牌前确认回环端口上是你自己的 daemon;本机 A2A 接口的第三方客户端(如 Hermes)不做这一步,按配置的地址直接发送令牌。daemon 启动时发现记录的端口被别人占着,不启动接口、不换端口,并在占用者可能是别的用户时更换令牌(`anet up`、`anet doctor` 会报告)。但如果别的本机用户只在 daemon 停机期间占住端口、收走令牌,又在 daemon 启动前放开,daemon 无从察觉;占用期间运行 `anet doctor` 可以发现。多用户机器上让 daemon 常驻,并在怀疑时删除 `a2a_token.txt` 后重启、`anet agents wire --refresh`。控制令牌同理:anet 自己的客户端不会把它交给占用者,但脚本里直接读 `control_token.txt` 调控制面的 curl 等不核实监听者;daemon 发现控制口被别的用户占着时会更换控制令牌,占用者若在 daemon 启动前已放开端口则同样无从察觉。
