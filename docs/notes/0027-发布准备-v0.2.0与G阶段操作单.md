## 3. ANetCore 打 v0.15.0 之后 ANet、ANetHub 的 go.mod 精确改动

### 3.1 做法与可信度

在 scratchpad 里用本地文件代理模拟 tag:`git archive` 导出 ANetCore 树,以 `golang.org/x/mod/zip.CreateFromDir`
打出 `v0.15.0.zip`,与原 `go.mod`、`.info` 放进代理目录;`GOMODCACHE` 指向 scratchpad(假 v0.15.0 不进真缓存,

在 ANet、ANetHub 的 `git archive` 副本里 `GOWORK=off go get github.com/ANetResearch/ANetCore@v0.15.0 && go mod tidy`,
然后 build、`go vet`(ANet:默认、`shell,taskboard`、`no_a2a`、全部减法;ANetHub:默认、`taskboard`、
`no_federation`)、`go mod verify`、`go test ./...`,全部通过。模拟所得 `v0.15.0` 的 `h1:` 与我用
`dirhash.HashZip` 独立算出的一致(`CEWd4…`,对应 ANetCore `2e7372d` 的树),说明方法本身可信。

   泄露后的恢复手段(见下"泄露")。**顺序不能反**:先备份、验证可解密且指纹一致,再删本机副本。
