## 2. 跨主机:两 hub 联邦 + 四个 daemon

部署(拓扑见 `topology.env`;本轮用一份只含 ink89/ink90 的 `TESTNET_TOPOLOGY`,见 §5):

```
deploy.sh ink90 hub2 ; deploy.sh ink90 daemon      # hub2 10.2.2.90:47201, d2a :47211(p2p :47231), d2b :47212
deploy.sh ink89 hub1 ; deploy.sh federate          # hub1 10.2.2.89:47101, hub1⇄hub2 delivery+discovery=allowlist
deploy.sh ink89 daemon                             # d1a :47111(p2p :47131), d1b :47112(p2p :47132)
```

测试准备(经 ssh 在主机上执行,令牌只在主机上读、经文件描述符交给 curl,不出现在命令行与本文):d2a、d2b 加
`cas` 模块;d2b 把 `cas.stat` 设为公开能力(因而发布 A2A 卡片);`d2a/peers.allow = {d1a, d1b}`,
`d2b/peers.allow = {d1b}`;四个 daemon `/visibility federated`。

## 5. 安全边界执行情况与偏离

- 只用了 `ink@10.2.2.89`、`ink@10.2.2.90`;没有 sudo,没有装包,没有改系统配置;所有文件在 `~/anet-testnet/` 下。
- 每个进程都有私有 `XDG_RUNTIME_DIR`(联调脚本在各自 `$J`/`$ROOT` 下,测试网在节点目录的 `xdg/`)。
- 停进程只按路径:联调脚本的 `stop_under`,测试网的 `deploy.sh stop <节点>`(pid 文件 + `/proc/<pid>/exe` 位于
  测试网目录下才发信号)。没有用 pgrep/pkill/killall。没有运行 `teardown.sh`(它会删掉日志)。
- 用过的 TCP 端口:Ink89 47100–47109、47150–47154、47160–47179、47400–47443(scenario,含第二个 hub 47401)、
  测试网 47101/47111/47112/47131/47132/47161/47162;Ink90 47201/47211/47212/47231/47261/47262。每次开跑前确认空闲。
- **偏离 1(端口)**:在修 F3 之前,`joint.sh` 第 1–4 次与 `joint-shell.sh` 第 1 次的 daemon 各自把本机 A2A 接口开在
  127.0.0.1:43811–43813(仅 loopback,当时空闲,随脚本收尾关闭)。发现后修掉并重跑,之后所有运行都在段内。
- **偏离 2(碰到生产主机,只读)**:部署后执行过一次不带主机名的 `deploy.sh status`,它按拓扑依次 ssh 到了
  dmax 与 cmax 并执行只读的 `rt_status`(`hostname`、检查 `/opt/anet-testnet` 是否存在;输出 "no testnet
  directory"),没有写入、没有启动任何东西。此后改用只含 ink89/ink90 的拓扑副本(`TESTNET_TOPOLOGY`)。
- 报告与日志摘录里没有令牌、私钥;`bridge.sh mirror` 没有运行,本机没有镜像任何令牌。
