### 1.2 调研改变了草稿的地方(提交前必须知道)

1. **A11 撤回。** A2A v1.0.1(2026-05-26 发布;改动来自 #1627,2026-04-14)把 `TaskNotCancelableError`、`ContentTypeNotSupportedError`
   的 HTTP 状态改成 `400`([A2A] `docs/specification.md:1183,1186`;`CHANGELOG.md` 1.0.1 节)。a2a-go 回 400 是**对的**;
   要求 409/415 的是钉在 v1.0.0 快照上的 TCK([TCK] `specification/version.json`、`tck/requirements/base.py:272,296`),
   上游已有 [TCK] #231、#240。
2. **A13 改投 TCK。** 规范要求所有 JSON 序列化用 camelCase([A2A] `docs/specification.md:1204`,§5.5),发
   `history_length` 的 TCK JSON-RPC 客户端才是不合规的一方;已有 [TCK] #242 与修复 PR #243,但 #243 只改了 GetTask,
   ListTasks 仍发 `context_id`、`page_size`、`page_token`、`history_length`、`status_timestamp_after`、`include_artifacts`
   ([TCK] `tck/transport/jsonrpc_client.py:215-235`)。据此建议 `0029` §9 第 1 条(module/a2a 预检把 snake_case 规范化)**不做**。
3. **A1 已有人报。** [GO] #445(2026-09-26,a2a-go 与 JS SDK 签名不互认)与 [A2A] #2122(§8.4.1 规范化规则不确定)。

4. **A3、A9 很急。** a2a-go 的卡片签名与验证(`a2acrypto`、`Resolver.Verifier`)首次出现在 v2.6.0(#368,2026-09-25 发布),
   用户还很少,越早私下报告越好。
5. **anet 自身两处与 A2A v1.0.1 不符**(本包不改代码,需另开工作包;已由 `wp/v101` 修复——`99bed37` 错误 Content-Type 回 400、接受 `application/a2a+json`,`9031eb7` 应答类型对称协商——随 `integ/round7b` 合入):

     `application/json`(同文件 :206),按 v1.0.1 发 `application/a2a+json` 的客户端会被拒。

### 2.5 扩展与协议绑定怎样被收录

- 任何人都可以自行定义、发布扩展与绑定;下面的分级与流程只适用于放在 `a2aproject` 组织下的
  (`extension-and-binding-governance.md:8-10`;`docs/topics/extensions.md:13`)。
- **两级**:官方 `ext-*`/`cpb-*`,实验 `experimental-ext-*`/`experimental-cpb-*`;官方 URI 前缀 `https://a2a-protocol.org/extensions/`、
  `…/bindings/`,URI 只是标识符,不要求可访问(`:12-34`)。扩展文档另建议把规范放在扩展 URI 上(`extensions.md:246-247`)。
- **官方的要求**:规范用 RFC 2119 语言;**Apache-2.0**;至少一个参考实现;宜在 A2A 网站有文档(`:42-48`、`:178-181`)。
- **实验的要求**:必须由一位 A2A Maintainer 赞助并由其建库;README 标明非官方;发布的包名要显示实验性质;TSC 可归档(`:50-66`)。
- **流程**:① 在 `a2aproject/A2A` 开 issue,写摘要、动机(为何核心协议或标准绑定做不到)、初步方案或草案 → 社区讨论(`:72-84`);
  ② 找到赞助 Maintainer、建实验仓库(`:86-94`);③ 实验期迭代(`:96-104`);④ 毕业:成熟度(生产级参考实现、文档、采用证据、
  维护承诺)+ 毕业 issue + TSC 表决(`:106-131`);⑤ 官方期的破坏性变更要新标识并经 TSC 评审(`:133-141`)。
- **SDK**:扩展与自定义绑定在 SDK 里必须默认关闭;官方绑定 SDK "SHOULD" 实现(`:155-174`)。
- **绑定规范必须写清的内容**:规范 §12([A2A] `docs/specification.md:2983-3076`)——**实现全部核心操作**(:2991)、数据模型等价、
  语义一致、数据类型映射、服务参数的传递方式(无头部的协议示例键名 `a2a-service-parameters`,:3018)、错误映射、流式、认证、
  卡片声明、互通测试;另见 `docs/topics/custom-protocol-bindings.md:39-121`,卡片以 URI 标识绑定(§5.8,规范 :1277)。
- **现状**:`a2aproject` 下只有两个实验仓库,`experimental-cpb-slimrpc` 与 `experimental-ext-oid4vp-auth`,都建于 2026-05-14
  (组织仓库列表 API)。赞助很少见。
- **注册表**:规范明言不规定注册表 API([A2A] `docs/topics/agent-discovery.md:59`),"社区在探索标准化"(:112)。
  它既不是扩展也不是绑定,**没有现成的收录路径**,只能以功能提案或文档提案的形式提出。
- **规范本身的改动**(⑥):改 `specification/a2a.proto` 要用 `feat:`/`fix:`,由 TSC 与项目 Maintainer 审(CODEOWNERS);
  ADR 模板在 `adrs/adr-template.md`,目前只有 TSC 作出的 ADR-001。

### 2.7 a2a-x402 的 scheme 收录

- `schemes/` 放"伙伴与贡献者起草的实验 scheme",不属于 x402 规范;成熟后应上游到 x402 主仓库的 `specs/schemes`
  ([X402] `schemes/README.md:1-7`)。现有 lightning、spark、uma 三份,其中 lightning 以 PR #23 加入(2025-09-23)。
- 待审:#137(2026-06-27)、#172(2026-09-01)、#185(2026-09-24);2026-05 以后只合入依赖类改动。

- **不建议用机器人账号或由 agent 直接提交。** 上游(x402-foundation 明文)对未经人审的 AI 产出很警惕;由 agent 持有令牌代发,
  出错时难以收回(已公开的内容无法撤回,`0027` G10 回滚一栏)。agent 可以在 fork 里准备分支与补丁,最后由提交人本人审过、点提交。
- **需要的授权**:
  1. PO 对每一份提交的同意(本文 §4 各步的"需 PO 同意");
  2. 公司对提交人的书面授权:可以代表 Agent Network Research 以 Apache-2.0 授权贡献内容,可以私下披露安全问题;
  3. a2a-x402 的 **Google CLA**:以公司名义贡献时由公司授权签字人签 Corporate CLA 并把提交人账号列入;以个人名义时签 Individual CLA;
  4. 若走 x402-foundation:提交人配置提交签名;
  5. 若 ⑤ 进入 `a2aproject` 实验仓库:接受治理文件的贡献者许可声明,并承诺维护。
