日期:2026-09-27。工作包 B5-05(DOCS-E2E)。依据:设计 §18"下游消费者本期只列影响清单"、
0011 §2.4 的盘点、计划 0014 B5-05 条目。

本文逐项列出三个直接调用 daemon 控制面或 hub 的下游程序,在 anet v0.2 与 hub wire 2 上会遇到的变化,
以及每项的迁移做法。三者都不在三个主仓内,本仓库的 CI 与联调覆盖不到它们;**迁移由各自的维护方在
v0.2 部署前完成**,部署与通知属于阶段 G(征求同意后执行)。

## 一、所有消费者共同的变化

| # | 变化 | 影响 | 迁移做法 |
|---|---|---|---|
| 1 | **wire 2 与 v0.2 同批部署**(设计 §18):旧 daemon 连新 hub 得到 426;新 daemon 连旧 hub 拒绝工作 | 消费者所在机器的 daemon 必须与它注册的 hub 同时升级 | 部署计划里把消费者所在节点(bmax 的 ai-studio 身份、Research-Galaxy 的实验节点、相框)列入同一批次;先升 hub,再立即 `anet update` + 重启这些 daemon |
| 2 | **入站默认 `closed`**(设计 X2、§5):允许名单之外的委派被拒(回签名的 `rejected`,`anet.reason=not_accepting`),**不写 interactions、不存内容**,所以不会出现在 `/threads`、`/inbox` 里 | 依赖"陌生人的委派先落进收件箱、再由 sidecar 判定"的消费者收不到任何新任务 | 把接受的委派方 AID 写进 `<数据目录>/peers.allow`(一行一个;daemon 每次判定重读,不必重启)。交互式运营用 `anet peers allow <aid>`(要求终端确认);脚本与服务直接写文件。需要"对任何人开放但只做确定性能力"的,改用 `inbound.public_capabilities`;确实要对任何人开放自然语言任务的,`anet inbound policy open`(终端确认) |
| 3 | **`accept_delegations` 迁移**(§5.1):配置里缺省或 `true` → `inbound.policy=closed`(日志提示一次),`false` → `closed`;daemon 首次启动后把该键从 `config.json` 删除 | 读 `config.json` 的 `accept_delegations` 判断"是否接单"的程序会读到缺省值,与 daemon 实际行为相反 | 改读控制面 `POST /status` 的 `inbound_policy`,或 `POST /peers/list`(策略 + 三份名单) |
| 4 | **`POST /accept`**:`{"enabled":true}` → **400**,错误信息说明三种策略与 `anet peers allow`;`{"enabled":false}` → 设为 `closed`。`/hub-register` 带 `accept_delegations:true` 同样 400,带 `false` 设为 `closed` | 调 `/accept on` 的启动流程失败 | 删掉 `/accept on` 调用,改为写 `peers.allow`(见第 2 条)。`accept off` 与 `accept_delegations:false` 可以保留,等同 closed |
| 5 | **结束语义**(设计"文本任务完成语义"、§4.2):provider 单方完成。`POST /end-accept` → **410 Gone**。provider 调 `/end` 即完成并签回执;requester 调 `/end` 是"请求完成",provider 的 daemon **自动**完成并签回执,不需要 provider 侧的程序参与 | 调 `/end-accept` 的代码得到 410;"等对方同意结束"的逻辑永远等不到 `end_accept` 消息 | 删除 `/end-accept` 调用与相关分支。provider 侧交付后直接 `/end`;requester 侧 `/end` 之后等 `state=completed` |
| 6 | **`/threads` 形状**:`status` 字段改为携带任务状态 `submitted` `working` `input-required` `completed` `failed` `canceled` `rejected`(与新字段 `state` 同值);`queued`、`ending`、`done` 不再出现(`done`→`completed`);`end_acc_by` 删除;新增 `state_seq`、`trust`、`capability`、`context_id`;消息新增 `msg_id`、`metadata`,`kind` 增加 `status`、`payment`,不再出现 `end_accept`;返回最新 1000 条交互,按状态时间降序 | 按 `status == "done"` 判断结束的代码永远不认为任务结束;按 `end_acc_by` 判断的代码拿到空值 | 终态判断改为 `state ∈ {completed, failed, canceled, rejected}`;"最后一条是对方的文本"只看 `kind == "text"` 的消息;`capability: true` 的交互是能力调用(确定性执行,不需要回复),跳过 |
| 7 | **`/pull`**(§7.7):总是写进新子目录 `<out_dir>/anet-<交互 id 前 12 位>/`;`out_dir` 必须是绝对路径,为空或相对路径回 400;落在数据目录或 exec 工作目录之内的 `out_dir` 被拒(先解析符号链接);同名文件换名,内容相同视为已取回 | 用相对路径或数据目录内路径取附件的代码得到 400;按"文件就在 out_dir 下"拼路径的代码找不到文件 | 传数据目录之外的绝对路径;文件路径以响应里 `files[].path` 为准(ai-studio 已经这样做) |
| 8 | **控制面加固**(§7):只接受回环 Host(`127.0.0.1:<port>`、`localhost:<port>`、`[::1]:<port>`),否则 421;`control_allow_remote` 删除,`control_addr` 非回环时 daemon 拒绝启动 | 从另一台机器或容器桥接地址访问控制面的部署失效 | 与 daemon 同机访问;跨机器用 SSH 端口转发 |
| 9 | **控制台票据**(§7.2):`/console` 页面不再嵌入控制令牌;浏览器凭 `anet console` 取的 60 秒单次票据换会话;会话只能调用白名单路由 | 抓取 `/console` 页面拿令牌、或把控制台 URL 长期保存的做法失效 | 程序一律用 `<数据目录>/control_token.txt` 的 Bearer 调控制面;给人看控制台用 `anet console --url` 现取现用 |
| 10 | **访客模式删除**(§9):hub 不再路由 `/guest/*`;`--guest-messages` 删除;`guest_messages` 参数被忽略 | 无功能依赖的只是多余参数 | 删掉该参数(不删也不报错) |
| 11 | **评价不带内容**(§9):`/review` 上传只含回执与评分、≤280 字符短评;hub `/stats.tasks_completed` 改为"经评价公开的有效回执数" | 依赖 hub 展示委派内容或按 `tasks_completed` 统计完成量的看板数字变小 | 完成量以本节点 `/threads` 或证据链为准 |
| 12 | **MCP 工具改名**(§12):`agents_find` `task_delegate` `task_message` `task_results` `task_inbox` `task_end` `evidence_read` `credit_balance` 删除(不保留别名),由 `list_agents` `send_message` `get_task` `list_tasks` `wait_task` `cancel_task` `reply_task` `submit_payment` `reject_payment` `get_balance` `audit` `node_status` `inbound_pending` `get_agent_card` 取代 | 按旧名写的 MCP 客户端权限规则、提示词、脚本失效 | 按新表改;`anet agents wire <工具>` 会重写受管的 MCP 配置 |
| 13 | **付款档位**(§8.6):新节点 `auto_max=0`、`agent_max=0`、`payees.allow` 为空;`/delegate` 的 `pay:true` 属"网关档",受 `explicit_max`(默认 10)与 `daily_max`(默认 50)约束,收款方必须在 `payees.allow` | 以前"`pay:true` 照价付"的调用在新节点上被拒 | 由运营者在终端 `anet payments set …` 设定上限,并把收款方 AID 写进 `payees.allow` |

## 二、ai-studio(`anetbridge.go` / `worker.go`)

现状:worker 每轮 `POST /threads`,只处理 `role == "inbound"`;`status ∈ {done, failed}` 视为结束;
`end_req_by == "them" && end_acc_by == ""` 时调 `/end-accept`;未在自带 ACL(`<data>/acl.json`,默认
allowlist)中的委派方回一条"未授权"文本;交付用 `/message`(JSON,`attachments` 为本机路径),随后 `/end`。

| 项 | v0.2 下的结果 | 迁移做法 |
|---|---|---|
| 自带 ACL | daemon 在 closed 下直接拒绝名单外的委派,worker 再也看不到它们;"未授权"提示那一段不会再被触发 | 把 `acl.json` 的 `allow[]` 同步到 daemon 的 `peers.allow`(写文件即可,每次判定重读);ACL 的 `open` 模式对应 `inbound.policy=open`(终端确认,且会让任何 AID 的自然语言任务落进收件箱)。建议保留 ACL 作为第二道门,但以 `peers.allow` 为准 |
| `worker.go:73` 结束判断 | `done` 不再出现,已完成的任务会被当成进行中 | 改为 `completed/failed/canceled/rejected` 四个终态 |
| `worker.go:79-86` 结束握手 | `end_acc_by` 字段消失(Go 解码为空串);`status` 又不再是 `done`,所以对方请求结束之后这个条件每轮都成立,每轮调 `/end-accept` 得 410 并刷日志 | 删除整段。requester 请求结束时 provider daemon 自动完成,worker 不参与 |
| `anetbridge.go:28,39` 注释的取值 | `kind` 可能是 `status`、`payment`;`status` 取新值 | 更新类型注释;`lastTextMsg` 已按 `kind == "text"` 过滤,保持 |
| `/message` 带本机路径附件 | Bearer 调用仍接受 JSON `attachments`(只有控制台会话被拒) | 不变 |
| `/pull` | 文件落在 `<out_dir>/anet-<ix12>/` 子目录 | `Pull` 已按响应的 `path` 取文件,不变;确认 `out_dir` 是数据目录之外的绝对路径 |
| 交付后 `/end` | provider `/end` 完成并签回执,不变;回执覆盖整段对话,`anet.reply` 取 provider 最后一条消息 | 不变 |
| `AGENT.yaml` 的 `runtime`/`monitor`/`ops`/`datasets`,`datasets.harvest: true` | hub admin 删除官方 agent 的 ops/monitor/insights/acl 路由与全部采集源(§9、C39),官方 agent 在 admin 中只登记 `id/aid/hub/caps`;"经 hub admin 远端管理 ACL"不再存在 | 清单只保留 `id/aid/hub/caps`;运维经 hub 主机之外的独立工具;生产上 `admin/datasets/*` 与 ai-studio manifest 的清理在设计 §9 清理清单内(阶段 G,征求同意) |
| 以 root 运行 | 与 v0.2 无直接冲突;若开启 exec 自动回复,沙箱与工作目录规则见设计 §6 | 建议改为非 root 专用账户(与官方 agent 部署样例 `deploy/official` 一致) |
