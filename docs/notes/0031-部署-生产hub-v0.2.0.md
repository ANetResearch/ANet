## 6. fmax 的 TLS:被阿里云未备案拦截阻塞

- `certbot certonly --webroot -w /var/www/certbot -d fmax.chatchat.space --dry-run` 失败:`Invalid response from
  http://fmax.chatchat.space/.well-known/acme-challenge/…: 403`。403 来自 `Server: Beaver`,即阿里云对未备案域名的拦截,
  不是 nginx(同一路径以 IP 访问得 nginx 的 404)。
- 拦截按 Host/SNI:`Host: fmax.chatchat.space` 的 80 端口请求绝大多数得 403(偶有放过,不足以通过 Let's Encrypt 的多视角
  验证);随后 **SNI 为 `fmax.chatchat.space` 的 443 连接也被重置**(`Connection reset by peer`,6/6)。所以即使换 DNS-01
  拿到证书,`https://fmax.chatchat.space` 也无法对外服务。
- 对照:同一台机器上 `Host: hub.agentnetwork.org.cn` 的 80 请求到达 nginx(5/5),SNI 为该名的 443 握手成功(5/5)——
  `agentnetwork.org.cn` 已备案,其子域不受拦截。两个域的 DNS 都在阿里云(hichina)。

建议(需要产品负责人/域名持有人):在 `agentnetwork.org.cn` 下加一条 A 记录指向 39.107.76.243,例如
`fmax.agentnetwork.org.cn`(下称 `<FMAX>`)。之后按下面执行(约 10 分钟,只新增文件,不动 `game*.conf`):

```sh
# fmax,root
install -d -m 0755 /var/www/certbot
# 站点:ANetHub deploy/nginx-hub.conf,server_name 与证书路径换成 <FMAX>,去掉 /install.sh、/install.sh.sig、/dl/;
# 文件名须排在 game*.conf 之后(例如 hub-<FMAX>),否则会成为 443 的缺省 server。先只放 80 块(ACME + return 404):
nginx -t && systemctl reload nginx
certbot certonly --webroot -w /var/www/certbot -d <FMAX> --dry-run && certbot certonly --webroot -w /var/www/certbot -d <FMAX>
printf '#!/bin/sh\nsystemctl reload nginx\n' > /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh; chmod 0755 $_
# 换成完整站点(80 跳 https + 443 反代 127.0.0.1:8088,access_log off、error_log crit、129m),nginx -t && reload
# unit 加 --public-url https://<FMAX>,daemon-reload,restart anet-hub
```

(另一条路是 Let's Encrypt 的 IP 证书:有效期约 6 天、certbot 2.9 不支持、需要另装 ACME 客户端并频繁续期,且 hub URL
会是 IP,之后换域名要让所有节点重新注册——不建议。)

   `location /` 为 96m,129m 更大)——若要完全回到原样,用 `/root/nginx-bak-20260928-164011/` 与本机快照
   `prod-before/`;`systemctl start anet-hub anet-hub-admin`。
