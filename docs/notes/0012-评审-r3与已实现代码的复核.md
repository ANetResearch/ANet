## 本轮唯一成立的发现

**位置**:`ANet/docs/A2A-DESIGN-zh.md` §10.3(卡片签名与规范化)、§10.1、§10.2。

**行为**:A2A 规范 §8.4.1–8.4.3 要求签名方和验签方在做 RFC 8785 规范化之前,先按
proto 字段的存在性规则去掉取默认值的非必填字段(如 `false`、`""`、`[]`、`0`)。
设计原文只写"对卡片去掉 `signatures` 后的 JSON 计算",没有这一步;a2a-go 的
`canonicalizeJSON` 同样只去 `signatures`,不去默认值,所以只跟 a2a-go 交叉验证
测不出这处遗漏。

**影响**:anet 卡片若在线上字段里带了任何一个默认值(例如扩展的 `"required":
false`、空的 `description`、空数组 `examples`),a2a-go 能验签通过,而按 proto
语义重建载荷的验证方(例如 a2a-python)会计算出不同的签名原像,验签失败;反过来,
anet 验证一张"按规范签名、线上保留了默认值"的第三方卡片时会误判为签名无效。
设计 §8.7 里"x402 声明 `required` 强制为 `false`"这条,如果照字面写成
`"required": false` 而不是省略该字段,就正好会产生一张跨语言验签失败的卡片。

**发现方式**:复核 agent 通读 A2A 规范 §8.4 与 a2a-go `a2acrypto/canonical.go`
后指出;经产品负责人未参与前提下的第二个独立复核 agent 反驳未遂,判定成立并给出
修正方案。

**修正方案(尚未实施,留给 C5/D1 任务落地时处理)**:
1. `a2acard` 定义卡片的"发布形":REQUIRED 字段必须出现;`optional` 字段仅在显式
   设置时出现;其余标量/repeated 字段处于默认值时一律省略(§8.7 的 x402 声明因此
   省略 `required` 字段,而不是写 `false`)。签名前断言输入已是发布形。
2. 验签时先按 AgentCard schema 去默认值(`params` 这类 `google.protobuf.Struct`
   内部字段不做这一步),再做 JCS;若该形式验签失败,回退到原始字节验签(兼容
   a2a-go 签发、保留了默认值的第三方卡片),验证结果记录用的是哪种形式。
3. 补一组用 a2a-python(经 proto → `MessageToDict` → 签名)生成的金标向量,含扩展
   params 与多个 skill,以及同一张卡片"线上带默认值"的变体。
4. §10.3 的检查补上 REQUIRED 数组至少一项的校验(`skills`、每个 skill 的
   `tags`、`defaultInputModes`、`defaultOutputModes`、`supportedInterfaces`),以及
   `name`/`description`/`version` 必须存在。
5. §10.2 的缺省 `SkillInfo.Description` 不能是空串(该字段是 REQUIRED),取能力
   id 或固定说明文本。

本条已通知给 C5(daemon 侧卡片生成)与 D1(本机 A2A 接口的代理卡片)任务,要求
在实现时一并处理。

## 本轮被反驳的发现举例(用于确认已落地代码没有回退)

以下三条摘自 47 条被反驳项,附独立复核给出的代码位置,可作为"C0/C1/C6 等关键约束
在当前代码里确实存在"的交叉印证(具体文件行号以复核时的代码状态为准,后续改动
可能已经移动):

- **EncKeySet 收件人绑定(对应设计 [C0])**:`ANetCore/seal/enckeys.go` 的验证
  函数按 `expectAID` 拒绝其他 AID 的合法 KEL+密钥集;`ANet/internal/daemon/
  seal_send.go` 的 `fetchRecipientKeys` 用请求的 AID 校验取回结果;
  `ANet/internal/daemon/peerkel.go` 的 `pinPeerKEL`/`notePeer` 回放 KEL 并在
  推出的 AID 与存储键不符时拒绝。
- **接收流程失败分类与重放行同事务提交(对应设计 [C1]/[C33])**:设计正文已把
  "任一步失败即 ack 并丢弃"改为按永久/暂时分类,重放行随业务写入在同一 SQLite
  事务提交,不再提前写入。

  `public_cap` 交互只接受 `cancel`、`end_request`(仅取 kind)与带
  `x402.payment.status` 的付款元数据,其余消息丢弃且不触发自动回复。
