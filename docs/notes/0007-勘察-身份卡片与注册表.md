## 0. 结论摘要

1. **现有 anet 卡片不是 A2A 可验证对象。** ADP 卡片用分离式 JWS,保护头固定为字节 `{"alg":"EdDSA"}`,无 `kid`、无 `typ`,验签时逐字节比对该头(ANetCore/adp/adp.go:253-256, 306-308);签名放在 `envelope` 而非 `signatures[]`(adp.go:98-107);字段为 snake_case(adp.go:151-183)。A2A 要求保护头含 `alg`、`kid`,`typ` 为 SHOULD(Refs/a2a/docs/specification.md:2076-2086),JSON 字段为 camelCase(specification.md:1204)。两者无法互验。
2. **本地目录回答的是未签名字段。** hub 的 `/agents` 与 `?cap=` 查询读 `agent` 表和 `agent_cap` 表(ANetHub/internal/aghub/aghub.go:552-614, 745-800),这两张表由注册请求体中未签名的 `name`/`caps` 写入(server.go:560;aghub.go:449-490);签名卡只作为附加对象存入 `agent_card`,且二者从不比对一致性(card.go:43-90)。卡片本身可选,无卡注册照常入目录(server.go:431-436, 552-558)。只有联邦来的条目取自签名卡(card.go:692-719)。
3. **身份层有两处会使"kid = AID + 密钥序号"方案失效的缺陷,目前潜伏(产品代码从未调用 `Rotate`)。** (a) hub 注册时用请求中提交的 KEL 覆盖已存 KEL,不检查新 KEL 是否为旧 KEL 的延伸(server.go:486-500;aghub.go:466-470),联邦卡同样覆盖(card.go:603-608),daemon 的对端 KEL 缓存无条件覆盖(ANet/internal/daemon/peerkel.go:61-64);(b) ADP 准入对卡片采用签名方自报 `issued_at` 的时间宽限,且过期卡(`DispExpired`)仍被 hub 存为当前卡(adp/admit.go:108-112, 148-153;card.go:70-89)。两者叠加时,已轮换掉的旧密钥可以重新登记或签发被接受的卡片 **[推断,代码路径已核实]**。
4. **推荐一个签名对象:以 A2A AgentCard 作为"卡片正本"**,ADP 的语义字段(seq、issuedAt、notBefore、加密公钥、价格、赎回地址)放进该卡 `capabilities.extensions[].params`,由同一个 JWS 覆盖;ADP 卡只在迁移期并行,并与 A2A 卡做一致性绑定。理由见 §8.1。
5. **签名**:EdDSA/Ed25519 JWS,保护头 `{"alg":"EdDSA","jku":<hub JWKS>,"kid":"did:anet:<AID>#<key_state_seq>","typ":"JOSE"}`;规范化用 a2a-go `a2acrypto`(RFC 8785 正确实现)而非 ADP 的手写 JCS。**[实测]** 以 `identity.Controller.CurrentPrivateKey()` + `a2acrypto.NewSigner` 签名、以自写的 KEL 回放 `KeyResolver` 验签通过;轮换后按"只接受 KEL 顶端密钥态"规则拒绝旧 kid。
6. **接口**:网络卡片(经 hub 发布)只放一个自定义绑定条目:`url` = 该 agent 所在 hub 的中继端点,`tenant` = AID,`protocolBinding` = anet 中继绑定 URI。A2A 的多租户文档明确允许以 agent 标识作 tenant(Refs/a2a/docs/topics/multi-tenancy.md:105-107)。127.0.0.1 接口**不进入**网络卡片;它出现在本机 daemon 在回环口提供的"本机代理卡片"中(§8.4)。
7. **不得自定义 SecurityScheme 变体。** proto 中 `SecurityScheme` 是封闭 oneof(a2a.proto:504-517);**[实测]** a2a-go 解析含未知 scheme 类型的卡片时整张卡解析失败(Refs/a2a-go/a2a/auth.go:196-200)。网络卡片省略 `securitySchemes`,认证由中继绑定内的发送方签名承担;本机代理卡片声明 HTTP Bearer。
8. **大整数不得以 JSON 数字进入签名卡片。** **[实测]** ADP 的 JCS 把 2^60 输出为 `1152921504606846976`,a2a-go 按 RFC 8785 经 IEEE 754 输出为 `1152921504606847000`;在 a2a-go 下,对前者的签名同样能验过后者。seq、金额一律用字符串。
9. **hub 注册表 API**:新增 `/a2a/v1/agents`(按 skill 精确/前缀、tag、全文检索)与 `/a2a/v1/agents/{aid}/card`(逐字节返回签名卡片,带 `ETag`/`Cache-Control`),`/agents/{aid}/jwks.json`(由 KEL 推导)。索引只从已验签卡片建立;条目包装层附 hub 自己的陈述(验证状态、lastSeen、homeHub),与签名卡片分开(§8.11)。

## 1. 身份层现状(ANetCore/identity)

### 1.1 AID 派生与 DID 形式
- AID = 初始事件(icp)CoreDet-CBOR 预映像的 CID(`anetcid.Sum`):identity.go:184-214(`Incept`),206;`AID()` 217。CID 为 multibase base32 CIDv1 dag-cbor sha2-256,形如 `bafyrei…`(ANetCore/anetcid/cid.go:6-11, 21-27)。
- AID 是自证明的:知道 KEL 的任何人可重算 icp 预映像的 CID 并与 AID 比对(`Replay` 第 0 条事件,identity.go:382-397)。
- DID 形式为 `did:anet:<AID>`(identity.go:219-220),但 ADP 卡片的 `subject_did` 实际写入的是裸 AID(ANet/internal/daemon/card.go:188 `SubjectDID: d.AID()`),字段名与内容不一致。

### 1.2 KEL 与 KeyState
- 事件类型:`icp`/`rot`/`ixn`/`dip`/`drt`(identity.go:34-40)。事件字段含 `Timestamp`(unix 毫秒,签名方填写)(identity.go:57-66)。
- `Replay` 校验:首事件为 icp;seq 严格 +1(402);prev 链接;rot 的新钥须匹配前一事件的 `next_digest`(pre-rotation)且由前一把当前钥签名(415-429);`drt` 追加委托钥但不改变签名钥(442-453)。seq 与数组下标一致,所以 `states[seq]` 即该序号的密钥态。
- 后处理:被后续 rot/dip 取代的密钥态标为 `rotated` 并记录 `SupersededAt`(460-474)。**ixn/drt 会增加 key_state_seq 但不换钥**,所以同一把钥对应多个连续的 seq。
- `Controller.Sign` 返回签名与当前 seq(235-239);`CurrentPrivateKey()` 返回 `ed25519.PrivateKey`,注释说明该钥同时用于 anet 对象签名与传输层(228-233)。
- `Export` 同时持久化当前钥与下一把钥的种子,注释说明这使本机存储的 pre-rotation 保证失效(90-109)。

### 1.3 VerifyObject 的时间感知撤销门
- 按声明的 `key_state_seq` 取钥验签(identity.go:503-521)。
- `msgTime == 0`:只拒绝声称终止态(dip)的签名(523-530)。
- `msgTime != 0`:已被取代的密钥态仅对 `msgTime < SupersededAt` 的对象有效(531-542)。`msgTime` 与 `SupersededAt` 都由签名方填写。

### 1.4 轮换在产品中的使用
- `ANet/`、`ANetHub/` 非测试代码中没有 `.Rotate(`、`.Deactivate(`、身份层 `.Delegate(` 的调用(grep 结果仅有 `control_api.go:658` 的任务委派 `d.Delegate`,与身份委托无关)。即 KEL 轮换目前只存在于 ANetCore。下文涉及轮换的缺陷均为潜伏状态。

## 2. ADP 卡片现状(ANetCore/adp)

### 2.1 结构
- `AgentCard`(adp.go:151-183):`subject_did`、`card_schema{major,minor}`、`seq`、`issued_at`/`not_before`(unix 秒)、`capabilities []string`、`domains`、`critical_extensions`、`genome`、`lineage`、`delegation_proof`、`envelope`,以及描述性字段 `id/name/description/version/skills/tools/endpoints/constraints/did/metadata/extensions/signature`。
- `EnvelopeJSON{signer_aid, key_state_seq, alg, sig}`,`sig` 为分离式紧凑 JWS `hdr..sig`(adp.go:98-107)。

### 2.2 预映像
- 规则为"整卡减去 `envelope`、`signature`,`card_schema` 只保留 major"(adp.go:187-214)。实现是先把 **Go 结构体**序列化再转回 map(196-203)。
- 后果:原始 JSON 中结构体不认识的顶层键不进入预映像,但 hub 按原字节存储并对外提供。hub 代码注释已写明"unknown JSON keys ride along unsigned"(ANetHub/internal/aghub/card.go:354-360)。**[实测]** 向已签名 ADP 卡片 JSON 插入顶层键 `"a2a":{...}` 后重算预映像,字节不变(cardprobe 输出 5)。因此"把 A2A 字段塞进 ADP 卡片的未知顶层键"不受签名覆盖。
- `extensions map[string]any` 在结构体内,**受**签名覆盖(adp.go:181)。现有价格表 `anet.pricing` 即放在这里(ANet/internal/daemon/card.go:205-211)。

### 2.3 JWS
- 保护头固定为 `{"alg":"EdDSA"}` 的确切字节(adp.go:253-256);签名输入 `b64url(hdr).b64url(preimage)`(261-264);线上形式省略 payload(268-270)。
- 验签时要求头部字节完全相等,否则 `INVALID_SIGNATURE`(adp.go:306-308)。**没有 `kid`、`typ`、`jku`**;签名钥由 `envelope.signer_aid` + `envelope.key_state_seq` 经 KEL 定位(admit.go:104-112)。
- 结论:A2A 验证方无法从 ADP 卡片取得 kid;ADP 验证方拒绝任何带 kid 的保护头。

### 2.4 JCS 实现与 RFC 8785 的差异
| 项 | ADP `jcs.go` | a2a-go `a2acrypto/canonical.go` | 影响 |
|---|---|---|---|
| 键排序 | `sort.Strings`,按 UTF-8 字节(jcs.go:76;注释承认只对 ASCII 等价) | 按 UTF-16 码元(canonical.go:186 起) | 键含 U+E000–U+FFFF 与增补平面字符时顺序不同 |
| 整数 | 保留原整数文本(jcs.go:106 起) | 经 float64 按 ECMAScript 规则输出(canonical.go:221-243) | >2^53 的整数输出不同 |
| 小数 | `strconv` 'g'(jcs.go:44-52) | ECMAScript `Number::toString` | 1e21 以上、1e-6 以下不同 |

**[实测]** ADP 预映像中 `2^60` 渲染为 `1152921504606846976`;a2a-go 对 `{"n":1152921504606846976}` 的签名,拿去验 `{"n":1152921504606847000}` 也通过(cardprobe 输出 6、7)。即 RFC 8785 下 >2^53 的整数存在两个 JSON 值共用一个签名的情况;anet 自己的实现则与其他 SDK 产生不同字节。

### 2.5 AdmitCard(admit.go:70-183)
1. 结构与尺寸:`name ≤ 128`、`description ≤ 4096`、legacy `skills ≤ 50`(84-86)。`MaxCardSize = 65535`(adp.go:54)定义了但全仓库无引用;`capabilities` 的数量不受 ADP 限制(hub 另有 `validateCaps`,见 §4)。
2. 验签:经 `identity.VerifyObject`,`msgTime = issued_at × 1000`(108-112)。
3. 自发布要求 `signer_aid == subject_did`;委托发布时只要 `delegation_proof` 非空即通过(115-128, 189-191)。
4. 任何 `critical_extensions` 条目都判 `CRITICAL_EXTENSION_UNVERIFIABLE`(51-54, 132-136)。
5. `seq > high_water`(139-142);`not_before ≤ now + 300s`(143-147);超过 `not_before + 7d` 返回 `DispExpired`,**不是拒绝**(148-153)。
- `CardStore`、`ParseGossip`、`CardTombstone` 在 ANet/ANetHub 非测试代码中无引用(grep 仅 card.go:280 的注释)。产品只用 `AgentCard`、`Sign`、`AdmitCard`。

## 3. daemon 发卡与注册现状

### 3.1 卡片内容(ANet/internal/daemon/card.go:185-220)
只填:`subject_did = AID`(188)、`card_schema.major = 1`(189, 32)、`seq`(190)、`issued_at = now`、`not_before = now − 1min`(191-192)、`capabilities`(193)、`critical_extensions = []`(194)、`name`(195);可选 `endpoints` 中的 `x402-redeem`(200-204)与 `extensions["anet.pricing"]`(205-211)。无 description、无技能描述、无输入输出类型。

### 3.2 seq
以 unix 秒为种子,同秒冲突时 +1,并持久化到 `<data>/card_seq`(card.go:104-183)。数值约 1.8×10^9,远小于 2^53。

### 3.3 注册请求
`registerWithHubLocked`(hub_client.go:56-87):请求体含未签名的 `name`、`caps`、`guest_messages`、`kel`,以及签名挑战 `ts/key_state_seq/sig`(62-71);签名卡作为 `card` 字段附带,**签卡失败时仍然注册,只记日志**(78-82);发出前经 `screenPublication` 做 INV-1/INV-2 过滤(83;modules.go:68 起)。挑战只签 `anet-relay/register/<aid>/<ts>`(ANetCore/relayauth/relayauth.go 的 `Preimage`),不覆盖请求体。

### 3.4 其他自述均未做内容签名
- `/profile`(summary/readme/pricing)只有挑战签名(hub_client.go:91-106)。
- `SetVisibility`、`LeaveHub`、`AdvertisePeerAddress` 均用同一 action `profile` 的挑战(hub_client.go:226, 253, 325)。

### 3.5 能力来源
- 注册的能力 = 配置中运营者声明的 `caps` ∪ C1 注册表中实际提供的能力(relay.go:460-478);启动时后台刷新注册(daemon.go:178-201)。
- C1 接口有 `Describe()`,注释称"daemon 把描述对象挂到 ADP 卡上"(ANet/provider/provider.go:40-43),但全仓库无调用点。C1 目前不提供任何人类可读的技能名称、描述、输入输出类型。可选接口模式已有先例:`Priced`(provider.go:60-66)、`LongRunning`(84-93)。

### 3.6 发现(客户端)
`FindByCapability`/`Find` 直接返回 hub 的 `AgentView`(relay.go:104-135),不取签名卡、不验签。客户端看到的技能与名称是 hub 的陈述。

## 4. hub 注册表现状(ANetHub/internal/aghub)

### 4.1 表
- `agent`(aid, name, caps JSON, summary, readme, pricing, guest_quota, kel, registered_at, …)(aghub.go:185-195)。
- `agent_cap(aid, cap)` 能力索引(219-224)。
- `agent_card(aid, seq, card BLOB, stored_at, fed_seq)`,按原字节存储(228-239)。
- `fed_card(aid, seq, card, kel, home, peer_aid, stored_at)`(383-391)。
- `review` 含 `goal`、`deliverable` 明文(196-210)。

### 4.2 `/register`(server.go:453-591)
1. 请求体上限 1 MiB(451)。2. `validateCaps(req.Caps)`:每 id ≤ 256 字节,每 agent ≤ 256 个(aghub.go:515-533)。3. 由提交的 KEL 推导 AID 并与声明比对(server.go:486-495)。4. 用**提交的 KEL** 验证挑战(498)。5. 邀请制准入(约 510-540)。6. 若带卡片:`AdmitCard`,主体须等于注册者、再过 `validateCaps` 与 ADP 准入(555;card.go:43-90)。7. `PutAgent(req.AID, req.Name, req.Caps, …, kelBytes)`,upsert 覆盖 name、caps、kel(server.go:560;aghub.go:466-470),并重建 `agent_cap`(aghub.go:477-489)。

### 4.3 查询
- 路由:`GET /agents`、`/agents/{aid}`、`/agents/{aid}/kel`、`/agents/{aid}/card`(server.go:195-198),全部匿名,CORS `*`(server.go:1085-1087)。
- `?cap=`:按 `agent_cap` 精确或尾部 `*` 前缀,字节比较(aghub.go:552-614);再并入联邦条目(server.go:782)。`?q=`:对 aid/name/caps/summary/readme 做 LIKE(aghub.go:745-800)。
- `/agents/{aid}`:返回 `AgentView` 与该 agent 的全部 review,其中含 `goal`、`deliverable`(aghub.go:855-903)。
- `/agents/{aid}/kel`:本地、联邦、departed、对等 hub 四种来源,并注明 `source`(server.go:1111-1177)。
- `/agents/{aid}/card`:原样返回 `agent_card` 字节(server.go:1179-1193)。

### 4.4 签名卡的实际消费者
- 支付网关:从签名卡读价格和赎回端点,并重新执行 `AdmitCard`(high_water=0,接受 `DispExpired`)(gateway.go:111-147, 157-199)。这是目前唯一依赖卡片签名的产品路径。
- 联邦:`FederatedAgents` 用签名卡的 name/capabilities 构造条目(card.go:692-719)。
- 本地目录不读签名卡。

### 4.5 联邦卡片同步
- 服务端:`GET /fed/v1/cards?cursor=`,匿名,返回 `{card(原字节), kel(base64), home, fed_seq}`(federation.go:501-521, 476-481;card.go:484-543)。只发本 hub 注册、可见性为 federated/public 的卡片,一跳(card.go:477-483)。撤回以 hub 自己的 `withdraw` 记录表达,不是 ADP 墓碑(card.go:268-294)。
- 拉取端:`SyncOnce` 每轮按游标拉取,`ErrRefusedForNow` 时停住游标(federation.go:613-717)。`AdmitFedCard` 检查 KEL 回放出的 AID 等于卡片主体(card.go:574-580),本地已注册的 AID 拒绝覆盖(584-597),再 `AdmitCard`,然后 upsert `fed_card`(603-608)。
- 模块化:联邦挂在 `//go:build !no_federation`(ANetHub/cmd/anet-hub/wire_federation.go:1, 18-28)。

## 6. A2A AgentCard 要求与 anet 现有数据对照

A2A 约束来源:a2a.proto:336-500;specification.md §5.7(必填数组至少一个元素,1263)、§8.4。

| A2A 字段 | 必填 | anet 现有来源 | 缺口 |
|---|---|---|---|
| `name` | 是 | `cfg.Name`(config.go:23),未签名注册体 | 可能为空,需兜底值 |
| `description` | 是(可为 `""`) | `cfg.Summary`,经未签名 `/profile` 发布(config.go:30;hub_client.go:91-106) | 需移入签名卡 |

| `version` | 是 | 无(ADP `version` 未填) | 用 daemon 版本或运营者设置 |

| `securitySchemes`/`securityRequirements` | 否 | 无 | 网络卡片省略;本机卡片 Bearer |

- `AgentCapabilities.pushNotifications`、`streaming` 无 `omitempty`,总是输出;`extendedAgentCard` 有 `omitempty`(Refs/a2a-go/a2a/agent.go:23, 26, 29)。**[实测]** 输出 1:`"capabilities":{"pushNotifications":false,"streaming":false}`。

## 7. 相关 A2A 规则摘录(设计依据)

- 发现:well-known URI、注册表、直接配置三种(specification.md:1984-1990);注册表 API 未标准化(topics/agent-discovery.md:59, 110-112)。
- 接口:`supportedInterfaces` 按偏好排序,客户端选第一个支持的(specification.md:1996-2010);自定义绑定用 URI 标识,破坏性变更换 URI(1277-1300, 3048-3066);官方绑定前缀 `https://a2a-protocol.org/bindings/`,实验性仓库 `experimental-cpb-*`(topics/extension-and-binding-governance.md:17-34)。
- tenant:客户端必须原样回填所选接口的 `tenant`(specification.md:2010;a2a.proto:345-350);服务方可用 agent 标识作 tenant(topics/multi-tenancy.md:105-107)。
- 签名:JCS 前按 proto 字段存在性处理默认值(specification.md:2020-2031);排除 `signatures`(2033);保护头 MUST 含 `alg`、`kid`,`typ` SHOULD 为 `JOSE`,`jku` 可选(2076-2086);验签可用 `kid`+`jku` 或可信密钥库(2132);过期或撤销的密钥不得用于验证(2143);可多签以支持轮换(2144)。
- 缓存:卡片端点 SHOULD 带 `Cache-Control: max-age` 与 `ETag`(2229-2230)。
- 扩展:声明于 `capabilities.extensions`,URI 带版本,破坏性变更换 URI(specification.md:1002-1141)。a2a-x402 v0.2 的 URI 为 `https://github.com/google-agentic-commerce/a2a-x402/blob/main/spec/v0.2`,推荐 `required: true`(Refs/a2a-x402-spec-v0.2.md:9-35);其激活头写作 `X-A2A-Extensions`(a2a-x402-spec-v0.2.md:428),A2A v1 正文为 `A2A-Extensions`(specification.md:1060),两者不一致。
- a2a-go `a2acrypto`:支持 EdDSA 推断与验证(alg.go:37-38, 53)、OKP/Ed25519 JWK(jwks.go:42);`KeyResolver` 为接口,`jku` 被视为不可信,只接受白名单(keyresolver.go:44-60, 88);客户端传输按 `protocolBinding` 注册,无匹配的绑定被跳过(a2aclient/factory.go:179-222, 251)。

## 8. 设计 [推断]

### 8.1 一个对象还是两个

| 方案 | 内容 | 优点 | 代价 |
|---|---|---|---|
| A. 单对象 | A2A AgentCard 为唯一签名卡片;ADP 语义字段进 anet 扩展 params | 一个签名、一个事实来源;任何 A2A 实现可解析;与"贡献而非竞争"一致 | hub 准入、网关、联邦需改为读 A2A 卡;ADP 的 golden vector 不再是线上格式 |
| B. 双对象并存 | ADP 卡继续用于内部;另签一张 A2A 卡对外 | 内部代码不动 | 两份自述会漂移。现状已有同类问题:注册体与签名卡并存且不比对(D1)。需要额外的交叉绑定与一致性检查,且双方都要维护 |
| C. 嵌套 | A2A 卡放进 ADP `extensions` | 一次准入即可签名覆盖 | 对外提供时要么拆出来(需 A2A 自身签名,即变成 B),要么外部客户端看到的不是 A2A 卡 |

推荐 **A**,迁移期内用 B 的受限形式:daemon 同时提交两张卡,hub 两者都验,并要求一致(A2A `skills[].id` 集合 = ADP `capabilities`,名称相等,价格相等,ADP 卡 `extensions["anet.a2a-card-cid"]` = A2A 卡规范化载荷的 SHA-256)。迁移完成后 hub 只要求 A2A 卡。ADP 包保留为规范实现与 golden vector,不再是注册线格式。

依据:ADP 保护头逐字节固定且无 kid(adp.go:253-256, 306-308),不能在不破坏 ADP-GV-1 的前提下改成 A2A 头;ADP 预映像由 Go 结构体决定,新增 A2A 字段需改 ADP 结构并重发 golden vector(adp.go:195-213);而 A2A 卡的 `capabilities.extensions[].params` 是任意结构(a2a.proto:424-434),足以承载 ADP 的 seq、时间与扩展数据,且位于签名载荷之内。

### 8.2 网络卡片(经 hub 发布、可联邦)

示例(占位 URI 以 `agentnetwork.org.cn` 为例,正式值待定):

```json
{
  "name": "code-reviewer",
  "description": "Reviews Go changes and returns findings.",
  "version": "0.21.0",
  "supportedInterfaces": [
    {"url": "https://hub.agentnetwork.org.cn/relay",
     "protocolBinding": "https://agentnetwork.org.cn/a2a/bindings/anet-relay/v1",
     "protocolVersion": "1.0",
     "tenant": "bafyrei…"}
  ],
  "capabilities": {
    "streaming": false,
    "pushNotifications": false,
    "extensions": [
      {"uri": "https://agentnetwork.org.cn/a2a/ext/anet-card/v1",
       "description": "anet identity, card sequence and encryption keys",
       "params": {"aid": "bafyrei…", "seq": "1790000000",
                  "issuedAt": "2026-09-26T08:00:00.000Z", "notBefore": "2026-09-26T07:59:00.000Z",
                  "encKeys": [{"kid": "…", "suite": "…", "pub": "…", "notBefore": "…", "notAfter": "…"}]}},
      {"uri": "https://github.com/google-agentic-commerce/a2a-x402/blob/main/spec/v0.2",
       "description": "Paid skills accept x402 payment"},
      {"uri": "https://agentnetwork.org.cn/a2a/ext/anet-pricing/v1",
       "params": {"network": "<hub AID>",
                  "prices": [{"skillId": "code.review", "amount": "5"}],
                  "redeemUrl": "https://…"}}
    ]
  },
  "defaultInputModes": ["text/plain", "application/json"],
  "defaultOutputModes": ["text/plain", "application/json"],
  "skills": [
    {"id": "code.review", "name": "Code review", "description": "…",
     "tags": ["code", "code.review"],
     "inputModes": ["text/plain"], "outputModes": ["text/plain", "application/json"]}
  ],
  "signatures": [{"protected": "<b64url(保护头)>", "signature": "<b64url(Ed25519)>"}]
}
```

字段规则:
- `name`:`cfg.Name`;为空时用 `"anet agent " + AID 前 12 位`。`description`:`cfg.Summary`(从未签名 `/profile` 移入签名卡)。`version`:daemon 构建版本,允许运营者覆盖。卡片修订号用 params.seq,不用 `version`。
- `provider`、`iconUrl`、`documentationUrl`:默认省略,运营者显式设置才输出。
- 所有必填切片初始化为非 nil;`streaming`、`pushNotifications` 显式输出(与 a2a-go 的无 `omitempty` 一致,使 a2a-go 反序列化再序列化后规范化结果不变);`required: false` 不输出(与 a2a-go 的 `omitempty` 一致)。
- 数值一律字符串(`seq`、`amount`);时间用 A2A 约定的 ISO 8601 UTC 毫秒(specification.md §5.6.1)。价格用 `[{skillId, amount}]` 数组,不用以 skill id 为键的对象,避免键排序实现差异。
- 零公开技能的节点**不发布卡片**:A2A 要求 `skills` 至少一项(specification.md:1263),而默认安全要求新装节点不对外提供服务。纯请求方只需 AID 与 KEL 即可收发结果。
- 发布前经现有 `screenPublication`(modules.go:68)过滤。

### 8.3 supportedInterfaces

- 网络卡片只包含与位置无关或由 agent 自己声明的入口:
  1. 中继绑定:`url` = 该 agent 的 hub 中继端点,`tenant` = AID,`protocolBinding` = anet 中继绑定 URI(v1),`protocolVersion` = `"1.0"`。hub 按 tenant 投递到信箱;载荷为端到端加密信封(03 报告 §5)。通用 A2A 客户端没有该绑定的传输,会跳过此条目(a2aclient/factory.go:179-222)并报"无兼容传输",这是预期行为:它们应通过本机 daemon 的代理卡片访问(§8.4)。
  2. 可选,p2p 模块在启用时追加直连条目(另一绑定 URI),由模块通过卡片贡献接口提供(§8.14)。现有 `AdvertisePeerAddress` 只有挑战签名(hub_client.go:320-333),放进卡片后地址本身受签名覆盖。
- 该 hub 地址受 agent 签名覆盖。现有联邦的 `home` 是 hub 陈述(card.go:259-264),拉取方把它当作路由依据(card.go:581-583 的注释说明了风险)。签名的接口 URL 使路由依据来自 agent 本人;hub 联邦时若 `home` 与卡片 URL 不一致,应以卡片为准并记录。
- **127.0.0.1 不进入网络卡片**:端口是每台机器的本地配置,对远端无意义,且会暴露本机信息。

### 8.4 本机代理卡片与 127.0.0.1 接口

外部 A2A 客户端(编码工具)只与本机 daemon 通信。本机 daemon 在回环口提供:
- `GET http://127.0.0.1:<port>/a2a/v1/cards/<remoteAID>`:本机代理卡片。内容由本机 daemon 在**本地验证远端网络卡片成功之后**生成:复制 name/description/skills/defaultModes;`supportedInterfaces = [{url: "http://127.0.0.1:<port>/a2a/v1", protocolBinding: "JSONRPC", protocolVersion: "1.0", tenant: "<remoteAID>"}]`(可再加 `HTTP+JSON`);`securitySchemes = {"anetLocal": {"httpAuthSecurityScheme": {"scheme": "Bearer"}}}` 及对应 `securityRequirements`;`capabilities.extensions` 中加入 `anet-origin/v1`(`required` 省略),params 含 `originCard`(远端网络卡片原字节,base64url)与 `originVerification`(`OK`/`UNVERIFIED`,取值见 §8.9)。
- 代理卡片由**本机 daemon 自己的密钥**签名(`kid = did:anet:<本机AID>#<seq>`,`jku` 指向回环口 JWKS),因为 URL 与 tenant 是本机 daemon 的陈述,不是远端 agent 的;远端 agent 的签名随 `originCard` 原样保留,需要端到端核验的客户端可以自行验证。
- tenant = 远端 AID 符合 A2A 多租户文档的设计意图(multi-tenancy.md:105-107),可回答 01 报告 §11 的第 1 个未决问题。
- 回环令牌应与控制面令牌分开:控制面令牌可操作整个 daemon(config.go:15-18;control_api.go:30-56),本机 A2A 客户端只需要发起委托与查询任务的权限。Host/Origin 校验与请求体上限见 01 报告 §3.5。

### 8.5 skills 的来源

- 来源一:C1 提供方。新增可选接口(与 `Priced`、`LongRunning` 同一模式):
  ```go
  type Described interface {
      SkillInfo(capability string) (SkillInfo, bool)
  }
  type SkillInfo struct {
      Name, Description string
      Tags, Examples, InputModes, OutputModes []string
  }
  ```
  不实现时:`name = id`,`description = ""`,`tags` 由 id 派生,`inputModes = outputModes = ["application/json"]`(C1 参数与效果都是 JSON,capability.go 顶部注释)。该接口不涉及"设备"概念,不违反 C1 红线(provider.go:6-9)。`Describe()` 的 CAS 描述对象方案无调用点,可以删除或由 `SkillInfo` 取代。
- 来源二:运营者声明的 `caps`(config.go:26-27),对应由 agent(auto-reply/exec 或外部编码工具)承接的服务。配置中为每个 cap 提供可选的 name/description/tags;默认 `inputModes = ["text/plain"]`。
- tags 派生:取能力 id 在 `@` 之前按 `.` 的各级前缀,例如 `ptz.absolute@onvif/camera-006` → `["ptz", "ptz.absolute"]`,再并入提供方声明,统一小写去重。每个 skill 至少一个 tag(a2a.proto:444 REQUIRED;specification.md:1263)。
- 只发布"公开技能"。仅对白名单对端开放的技能不写入网络卡片,由白名单对端通过带外方式获知。A2A 的扩展卡片(`GetExtendedAgentCard`)要求用卡片声明的安全方案认证(specification.md:3144-3160),而中继绑定的认证方式不在 A2A 封闭的 scheme 集合里;在上游有对应 scheme 之前不声明 `extendedAgentCard`。

### 8.6 capabilities.extensions

| URI | required | params | 说明 |
|---|---|---|---|
| `…/ext/anet-card/v1` | 省略(false) | `aid`、`seq`、`issuedAt`、`notBefore`、`encKeys` | 卡片元数据。不影响请求激活,所以不设 required,避免通用客户端因不认识而拒绝。`aid` 必须等于 kid 中的 AID 与 tenant。`encKeys` 即 03 报告 §5.2 的 `anet.enc/v1` |
| a2a-x402 v0.2 | 默认省略;全部技能收费时为 true | 无 | a2a-x402 推荐 true(spec 3.1),但 anet 存在同卡免费与收费技能并存、以及官方免费公共工具的情况;全局 true 会迫使所有客户端激活 x402 |
| `…/ext/anet-pricing/v1` | 省略 | `network`(结算 hub AID)、`prices[]`、`redeemUrl` | 取代 `extensions["anet.pricing"]` 与 `x402-redeem` 端点(card.go:34-58, 200-211);网关从这里读价(gateway.go:157-199 的对应改写)。由 x402 模块贡献,`-tags no_x402` 构建中不出现 |

`critical_extensions`、`domains`、`genome`、`lineage`、`delegation_proof` 在 daemon 中未使用(card.go:185-220),不映射。

### 8.7 securitySchemes

- 网络卡片:省略 `securitySchemes` 与 `securityRequirements`(二者非必填,a2a.proto:377-380)。认证由中继绑定承担:信封内发送方以 AID 签名(03 报告 §4.4、§5)。绑定规范需按 specification.md §12.6 写明这一点。
- 本机代理卡片:`httpAuthSecurityScheme{scheme: "Bearer"}`。
- 不定义新的 scheme 类型(§6,[实测] 输出 4)。如需在 A2A 层表达"以 DID/KEL 签名认证",向上游提议新的 `SecurityScheme` 变体(§10)。

### 8.8 签名

- 算法:EdDSA(Ed25519),签名钥为 KEL 当前钥 `CurrentPrivateKey()`(identity.go:233),直接作为 `crypto.Signer` 传给 `a2acrypto.NewSigner`(sign.go:51-70)。**[实测]** 输出 2 验证通过。
- 保护头(a2a-go 以 map 序列化,键按字母序):`{"alg":"EdDSA","jku":"https://<hub>/agents/<AID>/jwks.json","kid":"did:anet:<AID>#<key_state_seq>","typ":"JOSE"}`。
  - `kid` 用 DID URL 片段表示密钥态序号,anet 验证方据此回放 KEL 取钥(§8.9)。同一把钥覆盖多个 seq(ixn/drt 不换钥,§1.2),验证方按 seq 定位即可。
  - `jku` 仅供通用 A2A 验证方使用;a2a-go 要求 `jku` 在调用方白名单内(keyresolver.go:88)。
- 域分离:A2A 保护头含 `kid`,与 ADP 固定头(`{"alg":"EdDSA"}`)字节不同,ADP 验证方拒绝 A2A 签名,反之亦然;JWS 签名输入以 `eyJ` 开头,与 relayauth 的 `anet-relay/` 前缀及 CBOR 预映像不同。同钥跨协议的碰撞风险低但非零(01 报告 §4.2 已指出);如需完全隔离,可用 `drt` 委托一把卡片专用钥,但 `DelegatedKeys` 当前语义是"认证端点、不签 anet 对象"(identity.go:356-359),需要为卡片签名扩展该语义。建议先用当前钥,把专用钥列为未决问题。
- 规范化:用 a2a-go `a2acrypto` 的 RFC 8785 实现(canonical.go:31-267),不用 ADP 的 `jcsMarshal`(§2.4)。签名在 hub 与联邦中按原字节存储、转发;任何一方都不重新编码。
- 多签:A2A 允许多签(specification.md:2144)。计划内轮换时,轮换完成后立即用新钥重签并重新注册即可;不在轮换前用下一把钥签名(下一把钥的公钥在 KERI 中只以摘要承诺,提前使用会提前公开它)。

### 8.9 验证规则与诚实状态

anet 验证方(hub 准入、daemon 发现、本机代理):
1. 用 a2a-go 类型解析(保证通用可解析性);`signatures` 为空则拒绝(不沿用 a2a-go 解析器的放行行为,resolver.go:210)。
2. 解析 `kid` 为 `did:anet:<AID>#<seq>`;`AID` 必须等于 anet-card params.aid、所有中继接口的 `tenant`、以及(hub 准入时)注册者。
3. 取 KEL(hub:本地存储;daemon:本地缓存或 `GET /agents/{aid}/kel`),回放,验证回放得到的 AID 等于 kid 中的 AID。
4. **卡片只接受 KEL 顶端未被取代的密钥态**(`states[seq].Status == active`),不使用 `VerifyObject` 的时间宽限。卡片是"当前陈述",不是需要长期留存的历史凭证;宽限只应适用于回执等历史对象。**[实测]** 输出 3:轮换后旧 kid 被拒。
5. `params.seq` 大于该 AID 的高水位;`notBefore ≤ now + 300s`;超过 TTL 的卡片不作为当前卡片提供(区别于现行 `DispExpired` 仍存为当前卡)。
6. 尺寸限制:整卡 ≤ 64 KiB,`name ≤ 128`、`description ≤ 4096`,skills ≤ 256、skill id ≤ 256 字节(与现行 `validateCaps` 一致,aghub.go:515-533),每 skill tags ≤ 16。
7. 必填字段与"必填数组至少一个元素"(specification.md:1263)。

KEL 存储规则(修 D3):hub 与 daemon 只接受对已存 KEL 的延伸(旧 KEL 为新 KEL 的前缀,按 EventID 比对);长度相同但内容不同即为分叉,拒绝并记录;更短的 KEL 拒绝。这对 `agent.kel`、`fed_card.kel`、`peerKELs` 都适用。

状态表达(CLAUDE.md 诚实效果状态):注册表条目给出 `cardVerification`:
- `OK`:hub 在 `verifiedAt` 时刻按上述规则验证通过;
- `UNVERIFIED`:无签名卡片的旧式注册(迁移期保留,默认不出现在检索结果中,需 `include=unverified`)。
hub 的判定是 hub 的陈述;daemon 与本机代理必须自行验证。通用 A2A 验证方经 `jku` 取 hub 的 JWKS 时,密钥与 AID 的绑定依赖对 hub 的信任,等级低于 anet 验证方的 KEL 自证明;绑定规范与注册表文档须写明这一区别。

hub 对 KEL 仍可做的事:提供旧卡片与相应截断 KEL(回滚)。daemon 为每个 AID 记录已见的最高卡片 seq 与 KEL 长度,不接受回退 **[推断]**;更强的防护需要 KERI 式见证(未列入本期)。

### 8.10 JWKS 端点

`GET /agents/{aid}/jwks.json`:回放存储的 KEL,对每个 `status == active` 的密钥态输出一条 `{"kty":"OKP","crv":"Ed25519","x":<b64url 公钥>,"kid":"did:anet:<AID>#<seq>"}`。轮换后旧 seq 自动消失,通用验证方即不再接受旧签名(符合 specification.md:2143)。响应带 `Cache-Control: max-age=60`。

### 8.11 hub 注册表 API

路径放在新前缀下,不改变现有 `/agents` 的形状(web UI 与 wire 合同测试依赖它:ANetHub/internal/aghub/wirecontract_test.go:41;ANet/internal/hubapi/hubapi_test.go:25)。

1. `GET /a2a/v1/agents/{aid}/card`
   - 返回签名卡片原字节,`Content-Type: application/json`,`ETag: "<b64url(sha256(规范化载荷))>"`,`Cache-Control: max-age=300`;支持 `If-None-Match`(specification.md:2229-2230)。
   - 可直接交给 a2a-go 解析器:含非根路径的 URL 被原样获取(a2aclient/agentcard/resolver.go:86-88)。
2. `GET /a2a/v1/agents?skill=&tag=&q=&cursor=&limit=`
   - `skill`:能力 id 精确匹配,尾部 `*` 为前缀,字节比较,逗号为或(沿用 FindByCapability 的语义,aghub.go:552-592)。
   - `tag`:小写后精确匹配,逗号为或。
   - `q`:对 name、description、skill name/description、tags 做不区分大小写的子串匹配。
   - 不同参数之间为与。`?skill=` 为空值时 400(沿用 server.go:760-770 的行为)。
   - 默认只返回 `Browsable` 且 `cardVerification == OK` 的条目。
   - 响应:
     ```json
     {"agents": [
        {"aid": "bafyrei…",
         "card": { …签名卡片原样… },
         "cardVerification": "OK", "verifiedAt": "2026-09-26T08:00:05.120Z",
         "homeHub": "", "lastSeen": "…", "quiet": false,
         "reviewCount": 3, "avgRating": 4.7}],
      "nextCursor": "…"}
     ```
     包装层字段是 hub 的陈述,不属于签名内容;`card` 字段内嵌原字节(Go 中为 `json.RawMessage`,序列化时可能被压缩空白,规范化后等价)。不返回 review 中的 `goal`/`deliverable`。
3. `GET /agents/{aid}/jwks.json`(§8.10);`GET /agents/{aid}/kel` 保持不变。
4. 提交:`POST /register` 增加 `a2a_card` 字段。迁移期 `card`(ADP)与 `a2a_card` 并存并做一致性检查(§8.1);迁移完成后 `a2a_card` 为必填,注册体中的 `name`/`caps` 只作为旧客户端兼容,不再写入索引。
5. 索引:新表 `agent_skill(aid, skill_id)`、`agent_tag(aid, tag)`,只在卡片准入成功后由卡片内容重建(替换现在由 `req.Caps` 重建 `agent_cap` 的逻辑,aghub.go:477-489)。现有 `/agents` 视图在迁移后也从已验证卡片派生 name/caps,以修 D1。
6. 顺带修 D5:为可见性、注销、p2p 地址、profile 分别定义 action,并让签名覆盖请求体摘要,例如 `Preimage(action, aid, ts, sha256(body))`。可见性作为 agent 意愿,也可以直接进入卡片 params,变成受签名覆盖的内容。

### 8.12 联邦同步

- 新增 `GET /fed/v2/cards`,条目 `{format: "a2a-card/1", card, kel, home, fed_seq}`。不复用 `/fed/v1`:旧版拉取方会把 A2A 卡当 ADP 卡解析,得到 `MALFORMED_CARD`,并按"永久拒绝"推进游标(federation.go:674-700),该卡在旧版对端上从此不再被请求。
- `AdmitFedCard` 按 `format` 分派到 A2A 准入(§8.9),KEL 延伸规则同样适用于 `fed_card.kel`。
- 一跳规则、撤回语义、`ErrRefusedForNow` 游标规则保持不变(card.go:268-294, 477-483;federation.go:442-467)。
- `home` 与卡片中中继接口 URL 不一致时,以卡片为准并记录日志。

### 8.13 迁移步骤

1. 身份前置:KEL 只接受延伸(D3);卡片只接受顶端密钥态、过期卡不作当前卡(D4);挑战按端点分离并覆盖请求体(D5)。无需等待 A2A 工作,且与轮换上线直接相关。
2. ANetCore 新包(建议名 `a2acard`):构造、签名、验证、KEL `KeyResolver`、JWKS 推导、规范化载荷哈希;依赖 a2a-go `a2a` 与 `a2acrypto`(依赖闭包只有 uuid,无 grpc,见 01 报告 §2.1)。
3. daemon 注册时同时提交 ADP 卡与 A2A 卡;hub 两者都验并比对;新增注册表与 JWKS 端点;索引改从卡片建立。
4. 网关改读 anet-pricing 扩展;联邦 v2;daemon 的 `find` 改走新注册表并本地验签;本机代理卡片随本机 A2A 接口上线。
5. hub 不再要求 ADP 卡;`/agents` 旧视图从已验证 A2A 卡派生。

### 8.14 可插拔编译落点

- 网络卡片是注册(C2)与联邦(C3)的一部分,属于内核;daemon 与 hub 内核都会链接 `a2acard`(即 a2a-go `a2a` + `a2acrypto`)。需在实施时以 `go tool nm` 测量内核增量;01 报告测得含客户端与签名的完整组合 stripped 增量约 1.7 MiB,仅 `a2a`+`a2acrypto` 应更小 **[推断,未测]**。
- 本机 A2A 接口(`a2asrv`、本机代理卡片、回环令牌)为可选模块,建议 `no_a2a`,并加入 `.github/workflows/ci.yml` 的 tag 矩阵,双向验证符号数(CLAUDE.md "可插拔编译")。
- 模块向卡片贡献内容的接缝:仿 `Confidential`/`Payer` 的类型断言(module.go:184, 202),新增可选接口
  ```go
  type CardContributor interface {
      CardExtensions(ctx context.Context) []a2a.AgentExtension
      CardInterfaces(ctx context.Context) []*a2a.AgentInterface
  }
  ```
  x402 模块贡献 a2a-x402 与 anet-pricing 扩展;p2p 模块贡献直连接口。`-tags no_x402` 构建的卡片中不应出现 x402 相关 URI(测试见 §9)。

## 9. 测试要求 [推断]

对照 CLAUDE.md 的测试要求:

1. **Golden vector**:以 `identity.SuiteController()`(identity/suite.go:27-60,密钥公开、确定)构造固定 A2A 卡,钉住规范化载荷字节、保护头字节与签名字节;用 a2a-go `Verifier` + KEL 解析器验证;可选再用 a2a-python 交叉验证(a2a-go 已有 a2a-python 生成的 Ed25519 向量,01 报告 §0 第 4 点)。
2. **往返稳定性**:卡片经 a2a-go `json.Unmarshal` → `json.Marshal` 后签名仍然有效(防止 `streaming`/`pushNotifications`/nil 切片差异)。
3. **变异验证**(每条断言都要改坏实现确认失败):改 skill id、改 tenant、删 `signatures`、kid 中换 AID、kid seq 指向已轮换态、`params.seq` 不增、`notBefore` 超前、加入未知 scheme、数字改为 >2^53 的 JSON 数字、截断 KEL、分叉 KEL,均须被拒。
4. **契约测试**:新增注册表响应与 `a2a_card` 注册字段加入 `internal/hubapi/hubapi_test.go` 与 `internal/aghub/wirecontract_test.go` 的钉字段测试;绑定 URI 与扩展 URI 常量在 daemon 与 hub 两侧各自声明,由测试钉住字符串(与 `ExtPricing` 现状相同的做法:ANet card.go:48 与 ANetHub gateway.go:202)。
5. **fake 完整性**:daemon 测试中的 hub fake(ANet/internal/daemon/hubfake_test.go)须实现新准入的全部拒绝路径,不能只实现成功路径。
6. **联调**:`scripts/joint.sh`:daemon A 注册 A2A 卡 → hub 准入 → daemon B 经 `/a2a/v1/agents?skill=` 发现 → 本地验签 → 在回环口取代理卡片 → 用未修改的 a2a-go 客户端解析代理卡片并发起一次委托;`scripts/scenario.sh` 两 hub 联邦 v2;`scripts/prodtest.sh` 实网双 hub。
7. **tag 矩阵**:`no_a2a` 构建中 a2a-go `a2asrv` 符号为 0、完整构建 > 0;`no_x402` 构建产出的卡片中无 x402 URI(运行时断言)且 x402 模块符号为 0。

## 10. 可向上游贡献的内容 [推断]

1. a2a-go 卡片解析器增加"必须有有效签名"选项(resolver.go:210;01 报告 §4.3 C1)。
2. 在 A2A 仓库提 issue:签名卡片中 >2^53 整数在 RFC 8785 下的歧义(本报告 [实测] 输出 6、7),建议规范建议以字符串表示大整数。
3. 以实验性自定义绑定的流程提出 anet 中继绑定(`experimental-cpb-*`,governance 文档 §Lifecycle),内容为:tenant=AID 的路由、端到端加密信封、发送方签名认证、store-and-forward 下的流式语义说明(specification.md §12)。
4. 提出注册表 API 草案(agent-discovery.md:59, 110-112 明确尚未标准化),以 §8.11 为基础。
5. 提议新的 `SecurityScheme` 变体,用于"以 DID 文档/KEL 中的密钥对请求签名"的认证;在上游接受前,anet 不在卡片中使用自定义 scheme。
6. 将 KEL `KeyResolver` 作为独立小模块发布,作为 specification.md:2132 "可信密钥库"的一个实现示例。
7. 向 a2a-x402 指出激活头名称与 A2A v1 不一致(a2a-x402-spec-v0.2.md:428 对比 specification.md:1060)。

## 11. 未决问题

1. 绑定 URI 与扩展 URI 的正式命名空间(`agentnetwork.org.cn` 下的路径,或直接申请 `a2a-protocol.org/bindings/` 下的实验性名称)。
2. 卡片签名是否改用专用委托钥;若是,需要扩展 `drt` 委托钥的语义(identity.go:356-359)。
3. `did:anet` 是否登记为 W3C DID 方法;不登记也不影响 kid 的使用,但影响通用 DID 解析器的互通。
4. 迁移期长度,以及何时让 hub 拒绝无 A2A 卡的注册(与已部署旧 daemon 的兼容窗口有关)。
5. 官方公共 agent 的"官方"标记是否需要 hub 签名的背书对象(当前只能是注册表包装层的 hub 陈述)。
6. JOSE 的 `alg` 名称:部分新规范倾向用 `Ed25519` 取代多义的 `EdDSA`;a2a-go 目前只识别 `EdDSA`(alg.go:53)。本报告建议维持 `EdDSA`,是否需要双写待确认 **[推断,未核实相关 RFC 状态]**。
7. 可见性(hub-local/federated/public)是否并入签名卡片 params,取代单独的挑战签名端点。
