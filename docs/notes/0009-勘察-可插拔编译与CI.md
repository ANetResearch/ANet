## 1. 现状:可插拔编译机制

### 1.1 接缝:`module.Host` 与注册表

- `module.Host` 是模块能拿到的全部能力:`AID()`、`Providers()`、`RecordEvidence()`、`ResolveKEL()`、`PaymentSeam()`、`HubSeam()`(`ANet/module/module.go:51-116`)。**不含**委派、收件箱、消息、结果、结束、控制面地址或数据目录。扩大该接口被文档定义为"必须有人在这个文件里有意做出的决定"(`module.go:45-50`、`61-70`)。
- `TransportHost` 在 `Host` 之外加 `Inbound()` 与 `RegisterTransport()`(`ANet/module/transport.go:51-66`)。
- 注册:`module.Register(name, Factory)` 在模块包的 `init()` 中调用(`module.go:332-343`),重名 panic。`Factory` 返回 `(nil, nil)` 表示"编进来但未配置"(`module.go:271-274`)。
- `module.Build(cfg)` 对 `modules` 配置块中出现、但未注册的名字分三种情况报错(`module.go:421-444`):
  - `declaredCompiled(name)`:编进来但不是 Module(目前只有 `mcp`)→ "is reached as a subcommand … takes no config block"(`module.go:428-437`);
  - `optInName(name)`:加法 tag 模块 → "it needs -tags %s"(`module.go:439-441`);
  - 其他 → "built with no_%s?"(`module.go:438`)。
- `Compiled()` 返回注册表名字 + `extraCompiled`,排序(`module.go:368-378`);`anet version` 通过 `compiledModulesReport()` 打印(`ANet/cmd/anet/main.go:70-83`、`110-124`),空时打印 `(none)`。

## 2. MCP 北向的结构,以及它为什么不在 `module/` 下

### 2.1 结构(已读代码确认)

```
MCP 客户端 ──stdio──> `anet mcp`(短命子进程,cmd/anet/mcp.go)
                         └─ internal/mcpserv.New(Control, version)   9 个工具
                               └─ Control.Call(path, body, out)
                                     └─ HTTP + Bearer ──> 本机 daemon 控制面(127.0.0.1)
```

- `internal/mcpserv/mcpserv.go:1` 与 `mcpserv_test.go:1`:`//go:build !no_mcp`。
- `mcpserv.go:11-15`:作为短命 stdio 进程运行,不在 daemon 内;代理到本机 daemon 的控制 API;"a doorway that dies with the client is one that cannot outlive its authorization"。
- `mcpserv.go:31-36`:`Control` 接口只有 `Call(ctx, path, body, out)`,用于测试替身和限制可达端点。
- 工具与控制端点的对应(`mcpserv.go:42-197`):`agents_find→/find`、`task_delegate→/delegate`、`task_results→/results`、`task_inbox→/inbox`、`task_message→/message`、`task_end→/end`、`evidence_read→/evidence`、`credit_balance→/balance`、`node_status→/status`。
- `cmd/anet/mcp.go:32-54`:`daemon.ResolveControl(layout)` 取控制面地址与令牌;先 `/status` 探活,失败即拒绝启动;stdio 断开(EOF)视为正常结束。
- `cmd/anet/main.go:84-88`:未打 tag 的 `main.go` 里 `case "mcp": fail(runMCP(layout))`;`runMCP` 由 `mcp.go`(`!no_mcp`)或 `mcp_stub.go`(`no_mcp`)二选一提供。
- `main.go:1068`:`knownFlags["mcp"] = {}`。
- 内核 `internal/daemon` 中无任何 MCP 引用(grep `mcp`/`mcpServers`/`anet mcp` 无结果)。

### 2.2 为什么不在 `module/` 下

代码中写明的理由:

- `module.go:291-304`:MCP 北向"lives in internal/mcpserv and is reached as a CLI subcommand, so it never registers here";为了 `anet version` 不漏报,引入 `DeclareCompiled`。
- `mcpserv.go:11-15`:它是 daemon 之外的短命进程,不持有密钥与账本。

由结构推出的理由 [推断]:

- `module.Host`(`module.go:51-116`)不提供 `/delegate`、`/results`、`/inbox`、`/message`、`/end`、`/evidence`、`/balance` 对应的任何能力,也不提供控制面地址或令牌。MCP 工具面恰好需要这些。若做成 `module.Module`,就必须扩大 `Host`;做成子进程走控制面,则不需要动接缝。
- MCP stdio 由客户端按会话拉起,生命周期与 daemon 不同,放在 daemon 进程内不成立。

## 3. 新增减法 tag 模块(以 `no_a2a` 为例)的端到端清单

### 3.1 先要做的形态决定

A2A 北向与 MCP 北向有三处不同,决定了不能原样照抄 MCP 的形态 [推断,依据 A2A 规范的传输要求与现有代码]:

1. A2A 是 HTTP 服务(JSON-RPC / REST / SSE),外部 A2A 客户端主动连接,需要长驻监听 `127.0.0.1:<port>`;MCP 是客户端拉起的 stdio 短命进程。
2. A2A 服务需要配置(监听地址、鉴权方式、是否声明 x402 扩展)。按 `module.go:428-437`,一个"编入但非 Module"的子系统**不能**有 `modules.<name>` 配置块;若把配置放到 `Config` 顶层字段,则内核需要知道 a2a,违反 K207 式的隔离。
3. A2A 的流式接口(`SendStreamingMessage`、`SubscribeToTask`)需要事件推送。当前控制面没有流式端点(`internal/daemon` 中唯一的 `http.Flusher` 用于 `/shutdown`,`control_api.go:409`),子进程代理只能轮询 `/results`、`/thread`。

据此有两种可行形态:

| | 形态 A:`module/a2a` 作为 `module.Module` | 形态 B:`internal/a2aserv` + `anet a2a` 长驻子命令(仿 MCP) |
| --- | --- | --- |
| 配置 | `modules.a2a` 配置块,走现有 `Build()` | 命令行参数;`modules.a2a` 会被 `Build()` 拒绝 |
| 访问委派能力 | 需扩大 `module.Host`(新增一个窄的委派 seam,如 Delegate/Results/Inbox/Message/End/Thread/Balance),在 `module.go` 中显式决定 | 走控制面 HTTP,不动 `Host` |
| 生命周期 | 随 daemon 启停(`internal/daemon/modules.go:34-51`) | 需另行托管(systemd / `anet up` 拉起) |
| 事件推送 | 可在 seam 中提供回调或 channel | 需给控制面新增流式端点,或轮询 |
| `anet version` | 注册即出现 | 需 `DeclareCompiled("a2a")` |
| 内核改动 | `module.Host` 接口 + `moduleHost` 实现 | 可能新增控制面流式端点 |

两种形态都要求内核不 import `a2aproject/a2a-go`。

## 5. 发现的缺陷与不一致(位置 / 行为 / 影响 / 发现方式)

1. **组合行只检查第一个模块**
   位置 `ANet/.github/workflows/ci.yml:144`。行为:`mod="${mod%%,*}"` 只取第一个 tag。影响:组合行(如 `:109`、`:113-116`)不验证其余模块已被移除,"全部减法"构建的整体性质未被符号检查证明。发现方式:阅读 CI。
2. **`scripts/build.sh` 去掉符号表**
   位置 `ANet/scripts/build.sh:35`(`-s -w`)。行为:产物无符号表,`go tool nm` 返回 "no symbols"(依据 `build-release.sh:43-51` 的说明)。影响:对该脚本产出的二进制做可插拔检查恒为 0,无法区分"已移除"与"无法检查";`docs/DISTRIBUTIONS-zh.md:10` 的体积也以此口径测得。发现方式:对照 `build-release.sh:52` 的 `LDFLAGS='-w'`。
3. **`build.sh --check` 不验减法 tag**
   位置 `ANet/build.sh:52-62`。行为:只验加法模块默认不在。影响:提交前本地检查不覆盖 `CLAUDE.md` 要求的减法方向,这部分只有 CI 能发现。发现方式:阅读脚本。
4. **ANetHub 的 tag 只验"能编译"**

## 6. 结论要点

- 新增减法模块的最小集合:一个带 `//go:build !no_<name>` 的 blank-import 或声明文件(`cmd/anet/`)、模块代码全部打同一 tag、在 `ci.yml` `pluggable` matrix 中以该 tag **作为第一个**加一行、在符号模式中覆盖模块路径**与其第三方 SDK 路径**、`present/absent` 两个方向的 `Compiled()` 测试、`CLAUDE.md` 与 `DISTRIBUTIONS-zh.md` 同步。
- A2A 北向与 MCP 北向形态不同(长驻 HTTP、需要配置、需要事件推送),照抄 `internal/mcpserv` + 子命令的形态会遇到"非 Module 不能有配置块"(`module.go:428-437`)和"控制面无流式端点"两处限制;做成 `module.Module` 则必须显式扩大 `module.Host`。这是动手前需要先定的接缝决定。
- (a) 只改布尔默认值时,直接失败的是 `joint-shell.sh`(全部 8 节)、`container-shell-test.sh`、以及访客相关的 prodtest 9c / `4-guest.sh`;若 (a) 采用按请求方的允许名单,则 `joint.sh`、`joint-fleet.sh`、`scenario.sh`、`onboard.sh`、prodtest 大部分写路径、以及 36 处 `newTestDaemon(…, true)` 都要改。
- (b) 不影响 hub 转发路径本身;受影响的是 hub 作为内容一端的两处(访客代理、后台采集)以及两个直接调用 `ingest*` 的 daemon 测试(取决于解密放在哪一层)。
- (c) 牵涉 daemon、hub、ANetCore 契约、前端四处,并有两个会让联邦信誉静默失效的实现陷阱。
