## 7. canary

## 9. 遗留

1. **d1b 的工作集在 hub1 重启(t+140)后变大。** d1b 在前 150 分钟的 RSS 底在 35–45 MiB,hub1 停机恢复后负载期间在 85–175 MiB 之间,
   负载停后 10 分钟回落到 46–47 MiB,goroutine 21 个——不是泄漏(内存被归还、没有累积的 goroutine),但原因未定位:没有堆剖析手段
   (无 pprof,`GODEBUG=gctrace=1` 要改启动环境)。下一轮长稳可在一个 daemon 上带 `GODEBUG=gctrace=1` 看存活堆。
2. **F1 的轮询窗口。** 修复只管事件总线;轮询 `GetTask`/`/tasks/get` 的客户端在"报价入库"与"付款消息入库"之间(本机签名 + 一次写库,
   毫秒级)仍可能读到 input-required + needs_operator_approval。要彻底消除需要把"auto 档将付款"判定挪进报价的入库事务,代价是进程
   在两步之间停下时任务停在 working;本轮没有改。
3. **hub 停机时 daemon 每秒一行 "relay poll … connection refused"。** 不影响功能,停机 60 s 即 60 行;可考虑退避或按次数折叠日志。
4. **`fed_dedupe` 与 `replay` 表是有意的时间窗口(7 天、14 天)**,稳态行数随流量线性;F3 之后清理有索引,但窗口本身的容量没有上限。
5. 驱动里 Python 负载进程自己的 RSS 从 26 MiB 涨到 50–67 MiB(测试工具,不是被测对象),长于 4 小时的运行要留意。
6. 没有覆盖:cmax/dmax(campus 岛,0025)、他 uid 的占用者、hub 的 admin 进程(`HUB_ADMIN=0`)、`/x402/redeem` 与凭证兑付、跨岛联邦。
