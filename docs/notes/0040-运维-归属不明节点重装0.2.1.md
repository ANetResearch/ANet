### 3.4 账户 uid 调整(08:11–08:12)

改后快照里 dmax 出现 `anet-gpu2` 名下的两个 `systemd-resolved`(08-27 起):那是容器里的进程,容器与宿主共用 uid
空间,容器镜像的 `systemd-resolve` 是 uid 996,而 `useradd --system` 只看宿主 `/etc/passwd`,正好把 996 分给了
`anet-gpu2`。anet 有几处按 uid 认人(CLI 只把控制令牌发给同 uid 的 daemon,后端监听者核对),共用 uid 不可接受。
读取各运行中容器合并层的 `/etc/passwd`、`/etc/group`(只读,不进容器)与 `ps -eo uid=`:dmax 的镜像占用 uid 977、995–999,
gid 977、994–999;cmax 的镜像占用 uid 995–999、gid 993–999——cmax 上新建的 `anet-face`(995/994)、`anet-vision`(994/993)
也落在其中(暂无容器进程以这些号运行)。处理:停单元 → `groupmod -g`、`usermod -u -g` → `chown -R` 数据目录 →
核对 `/var/lib /run /opt /tmp /etc` 下无旧号文件 → 启动:

| 账户 | 原 uid/gid | 现 uid/gid |
|---|---|---|
| dmax `anet-gpu2` | 996 / 996 | 990 / 990 |
| cmax `anet-face` | 995 / 994 | 990 / 990 |
| cmax `anet-vision` | 994 / 993 | 989 / 989 |

重启后三个节点自动重新注册(emax `last_seen` 更新),doctor 同前;之后又做了一次 face 冒烟(第 5 节)。
`deploy/ops/README.md` 记下了选号方法。0034 建的 `anet-dmax`(997)、`anet-cmax`(996/995)也与镜像号重叠,不在本次范围,
未改(第 8 节第 2 条)。
