## 3. 当前代码的硬伤(C3 必须先处理)

1. **结算请求缺 `paymentRequirements`**:`module/x402/pay.go:205-235` `settle()`。真 hub 400。修法见 §5.3。
2. **账本读取无签名**:`module/x402/pay.go:282-316`(`Balance`)、`reconcile.go:70,85`。真 hub 401。修法:module 内实现 `hubSignedGet(ctx, path, action string, into any)`,照抄 `internal/daemon/hub_client.go:222-265` 的 `hubSigned`:`seam.Sign(relayauth.PreimageV2(action, aid, hubAID, ts, "GET", req.URL.RequestURI(), nil))`,头取 `internal/hubapi` 的 `HeaderAID/TS/Seq/Sig`,ts 用 module 自己的单调计数(hub 按签名防重放)。action 用 `relayauth.ActionBalance/ActionLedger/ActionRedemptions`。
3. **授权绑定原始 ix**:`paylink.go:200` `p.Authorize(*opt, id)` → `pay.go:164` 写进 `InteractionID`。实施 `pay_bind` 后,hub 不再见到 ix。
4. **报价是带回执的终态"结果"**:`paylink.go:149-165` → `deliverCapabilityResult`(`capability.go:456`)签回执并 `Finish(state=input-required, Receipt=…)`。后果:
   - `runCapabilityCall` 看到 `len(ix.Receipt)>0` 直接返回(`delegation.go:1031`),同一 ix 上的付款永远不会执行;
   - requester `ingestResult` 看到已有回执就当"已接受"(`delegation.go:1288`、`:1314`),付费后的真正结果会被丢弃;
   - `redeliveredDelegate` 会把"报价"当答复重发。
   所以报价必须改成 `anet.status/1`(StatusMsg),**不签回执、不写 Result**。
5. **fake hub 只实现了快乐路径**:`internal/daemon/hubfake_test.go:1022-1110`(`hSettle`)不读 requirements、不查绑定唯一、原因是散文、无 pending 注入;`hBalance`(`:1113`)不验签。C3 的测试必须先把 fake 补到与真 hub 同契约,否则所有新测试都在验一个不存在的线协(§17 "fake 完整性")。
6. **MCP 可以花钱**:`internal/mcpserv/mcpserv.go:63-97` `task_delegate` 的 `pay=true` → `/delegate pay:true`,按设计属 `gateway` 档,而"MCP 服务端不调用 task-manual、gateway、redeem 三类路由"。C3 删掉该参数(D2 再加 `submit_payment`/`reject_payment`)。

## 7. 陷阱

1. **不要让报价产生回执**:任何把 `Receipt` 写进 input-required 行的路径都会让后续付款与结果被当作"已答复"丢掉(§3 第 4 条)。
2. **结算前不得重做时效检查**:`Pending` 重试时授权可能已过 5 分钟窗口;hub 对已扣款授权仍回原回执,对未扣款的回 `expired_payment`(确定失败)。本地再检查一遍会把"其实已扣款"误判为过期。
3. **付款消息把 state 置 working**:`recoverInterrupted` 会误伤,见 §6.2。
4. **长调用槽要在结算前拿**,见 §6.2。
5. **fake hub 先补齐再写流程测试**:`hSettle` 要求 `paymentRequirements`(缺则 400 `invalid_payment_requirements`)、实现与真 hub 相同的 `CheckRequirements` 判定与 `duplicate_binding`、失败项带 `transaction=authID`、原因只用常量;加注入开关 `settleDelay`(睡过 daemon 超时后照常入账)、`settleOutage`(传输失败)、`pendingOnce`(回 `settlement_pending`);记录最后一次请求体以便断言 SI-1;`hBalance/hLedgerRead` 验 relayauth v2 签名(可复用 fake 里已有的 `sigSeen`)。
6. **`pay_required` 在 requester 侧存原始字节**(§8.7 逐字节比较要用);"逐字节"建议定义为 `json.Compact` 后相等,在 `SubmitPayment` 注释里写明。
7. **`taskNonce` 可能为空**(旧/恶意请求方的 TaskDoc 不带 `anet.nonce`,`taskNonce()` 返回 `""`,`delegation.go:269-280`)。`PayBind` 照算即可(双方都能算),但建议对标价能力要求 nonce,缺失即 `rejected`+`anet.reason=task_nonce_required`,避免两边对"空串"语义产生分歧。
8. **现有测试语义会变**:
   - `pay_test.go` 的 `TestThePaidLoopClosesEndToEnd`、`TestPayingWithoutCreditIsRefusedAsAPayment`(依赖两个 ix 与 `paidView`)要重写;
   - `release_qa_quote_test.go` 两个测试依赖 `awaitQuote`/报价即结果,改写为"第 9 步拒收非对端发来的 payment-required,且不自动付款";
   - `inbound_test.go:233` `TestAPublicCapabilityCallTakesNoText` 对**未报价**的运行中调用发 payment-submitted 并期望被接受——C3 之后应得到 `payment-failed{SETTLEMENT_FAILED, no_pending_quote}` 且不改状态;
   - SI-5 默认值(auto/agent 上限 0、payees 空)会让所有付费测试失败:加测试辅助 `setPayments(t, d, PaymentsConfig{…})`、`allowPayee(t, d, aid)`(直接写 `payees.allow`,不走 TTY CLI)。
9. **脚本**:`scripts/scenario.sh:441-470` 读 `payment_required`/`PAYMENT_REQUIRED` 结果、期望两个 ix;价格 25 > 默认 `explicit_max=10`;需要在配置里直接写 `payments` 与 `payees.allow`。`prodtest.sh:573` 用固定 reference `"prodtest"` 兑付,hub 的 `UNIQUE(payer,"redeem:prodtest")` 会让第二次运行得到 `duplicate_binding`,改为带时间戳的 reference。按 §17,脚本改动与 C3 同批。
10. **`VerifyReceipt` 钉本节点的 hub**(`pay.go:243-266`):requester 在非本 hub 账本上付款时(`pickRail` 回退),收据签名者是另一个 hub,只能记 `verified=false`。这是诚实结果,别当 bug"修"成放宽。
11. **`Settlement` 进入 `x402.payment.receipts` 前**:失败项 `transaction` 置 `""`、原值放 `extensions["anet.auth_id"]`;成功项原样保留 `extensions["anet.settlement.receipt"]`。
12. **payment 消息的正文**:`public_cap` 与能力交互上 text part 丢弃(已实现),但 `metadata` 里的 `x402.payment.payload` 必须保留——它就是 `pay_payload` 的来源。
