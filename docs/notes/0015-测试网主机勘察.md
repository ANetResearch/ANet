# 0015 · 测试网主机勘察

勘察日期 2026-09-27(主机时区 CST 为 09-28 凌晨)。对象是产品负责人授权用于联调的四台主机:
`root@10.2.2.89`、`root@10.2.2.90`、`root@cmax.anet.chat`、`root@dmax.anet.chat`。

本次**只读**:ssh 进去执行查询命令(`hostname`、`/etc/os-release`、`free`、`df`、`command -v`、
`systemctl list-units/list-unit-files/cat`、`ss -tlnp`、`ps`、`find -maxdepth 3 -iname '*anet*'`、
`<bin> --version`、`ufw status`、`iptables -S INPUT`、`curl` 外网与互通探测、`/dev/tcp` 端口探测),
没有安装、修改、重启任何东西,远端没有写任何文件(包括 `/tmp`)。唯一的副作用是 sshd 的登录记录。
没有读取任何 `config.json`、令牌、私钥文件的内容;单元文件只摘 `ExecStart/User/WorkingDirectory/HOME/ANET_DATA_DIR`
这几行,且对含 TOKEN/KEY/SECRET/PASS 的赋值做了脱敏。

据此写的脚本在 `scripts/testnet/`(用法与安全边界见其 README)。

## 1. 登录方式:授权名单上的地址有两处用不了

- Ink89/90 上没有 root,测试网在这两台只能以 `ink` 用户跑在 `~/anet-testnet/`,用 setsid + pid 文件,不能建

  **若要在这两台用 `/opt/anet-testnet` 与 systemd 单元,需要产品负责人把 ink88 的公钥加进它们的 root。**

## 3. 互通与出口

从每台主机(以及 ink88)对其余主机做 TCP 探测(`/dev/tcp`,4 秒超时;open = 连上,refused = 可达但没监听,
filtered = 超时)。端口取 22、80、443、4001、4002、8799、9443、18088、47000、47100。

| 从 \ 到 | Ink89/90(10.2.2.x) | dmax 10.253.20.5 | dmax 210.45.70.176 | cmax 10.253.20.9 | cmax 210.45.71.67 |
|---|---|---|---|---|---|
| ink88 | 全通(47000 refused) | 全通(47000 refused,22/80/443/4002/8799/18088 open) | 全部 filtered | 只有 22、4001、9443 open,其余 filtered | 全部 filtered |
| Ink89/90 | 全通 | 全部 filtered | 全部 filtered | 全部 filtered | 全部 filtered |
| dmax | 全部 filtered | —(本机) | —(本机) | 同 ink88→cmax:22、4001、9443 | 同左 |
| cmax | 全部 filtered | 全通(47000 refused) | 全通 | —(本机) | —(本机) |

结论:
- **两个岛**:lab(ink88、Ink89、Ink90)与 campus(dmax、cmax)。岛内互通,岛间不通。
- **ink88 是唯一的桥**:局域网到 Ink89/90,zerotier(10.253.20.2)到 dmax 全部端口、到 cmax 的 ufw 放行端口。
- **cmax 入站被 ufw 挡**:47xxx 从 dmax、从 ink88 都是 filtered。在 cmax 上监听的测试端口只有 cmax 本机能连。
- cmax 与 dmax 的公网地址在同一个 /23,彼此之间的"公网路径"不经过 NAT。授权主机里没有一对能测真实的公网 NAT 穿越。

### 对测试网的要求(已写进 `scripts/testnet/`)

1. 隔离目录 `/opt/anet-testnet/<run-id>/`,不复用 `/opt/anet-test`、`/data/anet-node`、`/root/.anet*`。
2. 端口段 47100–47499(勘察时全空);绑定具体地址而非 0.0.0.0;daemon 控制面只绑 loopback。
3. 专用单元名前缀 `anet-testnet-`,用 systemd 瞬态单元,不在 `/etc/systemd/system` 写文件。
4. 进程在沙箱里(`ProtectSystem=strict`、`ReadWritePaths=<run 目录>`、`ProtectHome`、`PrivateTmp`),
   `XDG_RUNTIME_DIR` 指向节点自己的目录 —— 否则 root 身份的测试 daemon 会写 `/tmp/anet-0/daemon.json`,
   覆盖生产 daemon 的指针。
5. **不要在 cmax/dmax 上直接跑 `scripts/joint.sh`、`scripts/scenario.sh`、`scripts/joint-fleet.sh`**:它们用
   `pgrep -x anet | xargs kill`、`pkill -x anet-hub` 按进程名杀进程,以 root 运行会杀掉上面列出的全部生产 daemon 与
   hub(宿主机 root 也能杀容器里的进程)。改造点见 `scripts/testnet/README.md`。
6. 不改 cmax 的 ufw。cmax 入站不通正好是一条要测的路径(p2p 失败后回落到 hub)。

## 5. 推荐拓扑

```
lab 岛(10.2.2.0/24)                              campus 岛(zerotier 10.253.20.0/24)
  Ink89  hub1 :47101  d1a :47111/p2p :47131          dmax  hub3 10.253.20.5:47301
                      d1b :47112/p2p :47132                d3a :47311/p2p :47331(可入站)
  Ink90  hub2 :47201  d2a :47211/p2p :47231          cmax  d4a :47411/p2p :47431(ufw 挡入站)→ hub3
                      d2b :47212                           d4b :47412 → hub3
                      off2 :47241(后端 :47242)
  hub1 ⇄ hub2 联邦(直连)                            hub1 ⇄ hub3 跨岛联邦:可选,经 ink88 ssh 转发
```

理由:
- Ink89/90 是唯一能做"真跨主机双 hub 联邦"的一对(两台都干净、互通、无生产服务);它们只有 2 核 3.8G,
  每台放一个 hub 加两三个 daemon 足够,不宜再多。
- official 放 Ink90 而不是 dmax:它要与两个 hub 上的节点联调,放在 lab 岛不需要转发;设计文档里"部署在 dmax"
  说的是生产,测试网不应把官方身份的测试进程与 dmax 的生产 voucher 网关放在一起。需要时在节点表里改一行即可。
- hub3 放 dmax(无主机防火墙,cmax 能连);cmax 只放 daemon —— 它的入站被挡,daemon 是纯出站客户端,不受影响;
  它的 anetpeer 监听端口对外不可达,构成"对端不可直连"的真实用例。
- dmax 的 hub 默认绑 zerotier 地址,不暴露到公网网卡;要测 210.45.x 地址路径时改主机表一行。
- 跨岛:lab 的 hub 与 hub3 无法直连;`bridge.sh fed-up` 在 ink88 上把 hub3 映射到 10.2.2.88:47301、把 hub1 映射到
  10.253.20.2:47101,再 `FEDERATE_BRIDGED=1 deploy.sh federate`。这条路径经过 ssh 转发,测的是联邦逻辑而非网络。
