## 1. 结论摘要

1. **一行安装没有签名校验，且 sha256 校验失败时仍继续安装。** `checksums.txt` 与二进制来自同一源（`install.sh:140`），缺文件、缺条目、缺 sha 工具三种情况都只打印 Warning 后照常安装（`install.sh:149-154`）。发布脚本不产生任何签名（`build-release.sh` 全文无 sign 步骤）。
2. **`anet install --agent` 只写 persona 文本，不注册 MCP。** 六个 install 函数都只写一份 Markdown（`agents_install.go:12-108`）；全仓检索 `mcpServers|mcp_servers|claude mcp|mcp.json|config.toml|opencode.json` 无命中。`docs/GUIDE-zh.md:241` 写"`anet install --agent claude` 会顺手把 MCP 配置写好"，与代码不符。
3. **persona 文本已过时，且与"默认安全"冲突。** 它写"v0.1 … pricing is display-only (no settlement yet)"（`install.go:25-27,37`），而 x402 付费已实现；它指示 agent 自行发布 profile、接活赚钱（`install.go:35-42`），与"新装节点不接受任何委派"的决策相反。
4. **当前默认值不满足决策 (3)。** `AcceptDelegations` 未设置即为 true（`config.go:94`、`config.go:114-116`），访客试用消息默认 5 条（`config.go:87-90,99-100`）；自动应答循环对所有活跃会话生效，无请求方过滤（`autoreply.go:272-301`）。
5. **MCP 工具面与 A2A 概念不对齐，且有描述与实现不符之处。** 9 个工具（`mcpserv.go:42-197`）；无工具注解（`Annotations` 出现次数 0）、无 server instructions（`mcpserv.go:40` 传 nil 选项）；`task_results` 描述提到 `receipt_verified` 但输出结构没有该字段（`mcpserv.go:101-106` vs `:259-267`）；`node_status` 描述提到"compiled-in modules / currently working on"（`mcpserv.go:191-192`），`hStatus` 不返回这两项（`control_api.go:367-400`）。
6. **`anet mcp` 使用宽松的控制面解析。** `runMCP` 调 `daemon.ResolveControl`（`mcp.go:34`），不是 `ResolveControlStrict`，被选身份不可达时会回落到 uid 指针指向的另一个 daemon（`control_api.go:82-103`）。注册 MCP 时若固定 `ANET_ID`，拼错不会报错。
7. **付款只靠工具描述里的一句话约束。** `task_delegate` 描述写"ask its operator first"（`mcpserv.go:73-74`），daemon 侧没有支出上限（全仓检索 `budget|max_spend|spend_limit` 无命中）。
8. **证据链可读，但只有 JSON 原样输出。** `anet evidence` 直接缩进打印 `/evidence` 的 JSON（`main.go:1490-1512` → `main.go:1561-1588`）。链上有 11 类事件，但入站委派被拒、消息往来、策略变更、自动应答调用都不在链上（见第 11 节）。
9. **目标工具的非交互注册方式各不相同**：Claude Code 有 `claude mcp add -s user`（本机 help 已核实）；Hermes 的 `hermes mcp add` 是交互式的（`mcp_config.py:438-600` 中有 `input()` 与 `_confirm`），需直接写 `~/.hermes/config.yaml` 的 `mcp_servers`；Cursor、Codex、opencode 的配置位置为 [推断]。
10. **Windows 目前无法一行安装。** `install.sh` 只接受 linux/darwin（`install.sh:88-92`），发布只出四个平台（`build-release.sh:71`）。另外 `agents.go:144,149` 在无 build tag 的文件里使用 `syscall.SysProcAttr{Setpgid}` 与 `syscall.Kill`，[推断] Windows 目标无法编译 `internal/daemon`。

### 2.2 校验链的问题

- **同源校验，信任根只有 TLS 与域名。** 二进制与 `checksums.txt` 都来自 `FOUND_BASE`（`install.sh:121,140`）。能改源站的一方可以同时改两者。该校验只能发现传输损坏，不能发现源站被替换。
- **失败时放行。** `checksums.txt` 取不到（`:152-153`）、没有匹配条目或没有 sha 工具（`:149-150`）都只打 Warning。影响：攻击者让 `checksums.txt` 返回 404 即可绕过校验。
- **先解压后校验。** `gunzip` 在 `:134`，校验在 `:140`。未经验证的数据先交给解压器处理。`build-release.sh:85` 只对原始二进制算 sha256，没有 `.gz` 的哈希，所以现在也无法先校验压缩包。
- **`VERSION` 不受校验约束**（`:130`），只是显示。无防回滚：源站可以提供旧版本的合法二进制与对应的 `checksums.txt`。
- **下载地址不限定 https。** `--base` 与 `ANET_INSTALL_BASE` 原样使用（`:50,65-66,80`）；`curl` 没有 `--proto '=https'`（`:123,130,140`）。[推断] curl 默认允许 https→http 的重定向。
- **脚本未包成函数。** 顶层语句直接执行，[推断] `curl | sh` 时下载中断会执行半截脚本。
- **`--help` 在管道模式下无输出。** `sed -n '2,20p' "$0"`（`:74`），经 `curl | sh -s -- --help` 运行时 `$0` 是 `sh`。

### 2.3 与既有运维记录的关系

memory `anet-release-pipeline` 记录：线上 `/dl` 自 2026-07-25 起停在 0.1.5，0.1.6–0.1.9 发到了 nginx 不读的目录；`docs.agentnetwork.org.cn/dl/…` 返回 200 的 SPA 兜底页。`install.sh:50` 的第一个候选源是 `https://agentnetwork.org.cn`。[推断] 若该域名对 `/dl/*.gz` 也返回 200 的 HTML 兜底页，`curl -f` 会成功、循环停在这个源，随后 `gunzip` 失败，脚本在 `set -e` 下退出，不会尝试第二个源。本次未能离线核实该域名 `/dl` 的实际响应。

### 2.4 安装后状态

- 不带 `--hub` 时不启动 daemon（`:206`），只打印提示。
- 不检测、不配置任何编码 agent 工具。
- 输出末尾把用户引到 hub 网页和 hub 的 `llms.txt`（`:250-253`）。`ANetHub/internal/aghub/web/llms.txt:86-95` 要求 agent"无条件"执行 `curl … | sh`。整条链路没有签名，信任根是 TLS 与域名。

补充一条 `05-secure-defaults.md` 未展开的链路 **[推断]**：

- 入站附件的 `Mime` 由对端决定，存储时只校验 CID（`attachments.go:130-140`）。
- `/attachment` 对 `text/*` 类型不加 `Content-Disposition`（`control_api.go:784-786`），会在 daemon 的回环源上内联渲染。
- 同一个源的 `/console` 返回令牌（`console.go:29-41`）。

因此，对端发来一个 `text/html` 附件，操作者在控制台点开后，[推断] 页面脚本可以同源读取 `/console` 拿到令牌，再调用任意控制面接口。本地 A2A 接口若与控制台共用同一监听口和同一个源，会继承这个问题。

**端到端加密现状**：`relaySend` 把 payload 原样交给传输层（`transport.go:104-131`）；`ANetCore/identity/encrypt.go:73` 的 `SealTo` 在 ANet 中没有调用点。`skill.md:11-12` 写"hub 看得见谁在跟谁说话，看不懂内容能不能被验证"，没有清楚说明内容目前未加密。决策 (2) 落地后，skill.md 需要重写这一段；落地前不应暗示内容保密。

## 8. 提案 A：一行安装应做的事 [建议]

### 8.1 命令形态

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://agentnetwork.org.cn/install.sh | sh
```

可选参数：

- `--agents claude,codex`：只接入指定工具；默认接入检测到的全部工具
- `--no-agents`
- `--no-start`
- `--hub URL`
- `--shell`：保留，选择变体
- `--prefix`

**不提供**跳过签名校验的参数。需要离线安装的用户走手动路径（下载、`ssh-keygen -Y verify`、`sh install.sh --from-dir DIR`）。

### 8.2 步骤

1. **脚本结构**：全部逻辑放进 `main()`，最后一行调用 `main "$@"`；所有 curl 调用加 `--proto '=https' --tlsv1.2`；`--base` 只接受 `https://`。
2. **取清单并验签（失败即退出）**：
   - 取 `release.json` 与 `release.json.sig`。清单含版本、提交、发布时间、失效时间、每个资产的 `.gz` 与原始文件 sha256、每个变体应含/不含的模块名。
   - 用脚本内置的 Ed25519 公钥验签，工具用 `ssh-keygen -Y verify`（见 10.2）。
   - 验签失败、清单过期、或版本低于已装版本（未给 `--allow-downgrade`）时退出。
3. **下载并双重校验**：先校验 `.gz` 的 sha256，再解压，再校验原始文件 sha256。任一失败即退出，不打 Warning 放行。
4. **原子安装**：沿用 `install.sh:157-171` 的写法。写一份安装记录 `~/.anet/install.json`，含版本、两个 sha256、签名公钥指纹、来源 URL、时间。
5. **自检二进制**：运行新二进制的 `anet version`，把 `modules:` 行（来自注册表，`main.go:70-83`）与清单里该变体的模块集合比对，不一致即回滚。
6. **初始化安全默认值**（新命令 `anet init`，幂等，已有配置不覆盖，只补缺省键并报告差异）：
   - `accept_delegations: false`（显式写出）
   - `guest_messages: 0`
   - 无 `auto_reply`
   - `visibility: hub-local`
   - 支出上限 0
   - 本地 A2A 接口绑定 127.0.0.1，使用独立 bearer 令牌，并校验 Host 与 Origin
   - 这要求把 `config.go:94` 的"未设置即接受"改为"未设置即拒绝"，并为既有用户提供迁移说明（见第 12 节）
7. **启动 daemon**：`anet up`。[建议] 另提供 `--service`，安装 systemd user unit 或 launchd agent，使 daemon 在重启后恢复。默认不装服务。
8. **向 hub 注册**：投递信箱需要注册。以 `hub-local` 可见性注册；卡片声明"不接受委派"。是否需要"注册但不列入目录"的选项，涉及 ANetHub，列为未决问题。
9. **检测并接入编码 agent 工具**：新命令 `anet agents wire [--all|<id>…]`。
   - 检测依据：可执行文件在 PATH 上，**且**工具的配置目录存在。只有目录存在不算，避免 `/opt/data` 类误报。
   - 优先调用工具自带的非交互 CLI（`claude mcp add -s user …`）；没有这类 CLI 时写配置文件。
   - 写文件前备份为 `<file>.anet-bak-<ts>`，使用托管标记，写入绝对路径与 `ANET_DATA_DIR`。
   - Claude Code：技能写到 `~/.claude/skills/anet/SKILL.md`，不再写入 `~/.claude/CLAUDE.md`。Codex/opencode/OpenClaw 的 `AGENTS.md` 块压缩到只指向 MCP 工具，[建议] 不超过 600 字节。
   - Hermes 保留 `SOUL.md`，并写入 `mcp_servers`。
10. **验证并打印可核验状态**：新命令 `anet doctor`，带 `--json`。
    - 按 `scripts/mcp-probe.py` 的方式实际拉起 `anet mcp` 完成握手并列出工具。
    - Claude Code 另跑 `claude mcp get anet`。
    - 读取 `/status`。
    - 打印下面的状态块。
11. **给出第一个可用操作**：列出官方公开 agent（决策 (3)），附一句可以直接对编码助手说的话。

## 9. 提案 B：MCP 工具按 A2A 概念重组 [建议]

### 9.1 原则

- 工具名对齐 A2A 操作（`a2a.proto:19-131`；`specification.md:151-404`）。
- 返回值使用 A2A 的 Task/Message/Artifact JSON 形状，anet 特有信息放进 `metadata`，命名空间为 `anet.*`。

## 10. 提案 C：供应链 [建议]

### 10.1 现状的信任根

只有 TLS 证书与两个域名（`install.sh:50`）。发布在开发机本地构建（`build-release.sh` 全文；`ci.yml` 无 release job），上传路径经过 ModelScope 中转与 cmax（memory `anet-release-pipeline`）。中间任一环节被替换，用户侧都无法察觉。

### 10.2 发布签名：Ed25519，用 `ssh-keygen -Y` 验证

- **选择理由**：
  - install.sh 必须用 POSIX sh 加系统自带工具完成验签。
  - [推断] OpenSSH 8.1 起支持 `ssh-keygen -Y sign/verify`，主流 Linux 发行版与 macOS 默认自带，且支持 Ed25519。
  - minisign/signify 不预装；cosign 不预装。
  - [推断] openssl 的 `pkeyutl -verify -rawin` 在 macOS 自带的 LibreSSL 上是否可用不确定。
- **签名对象**：`release.json`（见 8.2 第 2 步），不单签每个二进制。签名命名空间用固定字符串 `anet-release@agentnetwork.org.cn`，防止同一把钥匙签出的其他文件被当作发布清单使用。
- **公钥分发**：同时写在 `install.sh` 内、仓库 `SECURITY.md`、官网文档、GitHub README 四处，任何一处都可用来核对。
- **install.sh 自身**：`curl | sh` 这条路径上，脚本本身仍只依赖 TLS。提供手动路径 `curl -O install.sh install.sh.sig && ssh-keygen -Y verify … && sh install.sh`，并在文档中说明两条路径的差别。
- **daemon 内更新**：新增 `anet update`，用 Go 标准库 `crypto/ed25519` 验同一份清单，不增加依赖。把 hub `llms.txt:86-95` 的"无条件 `curl | sh`"改为 `anet update`。

### 10.3 钥匙保管与轮换

- 私钥离线保存（硬件令牌或离线机），不放在构建机上。
- 清单里带 `next_key_fingerprint`，做预轮换：下一把钥匙的指纹由当前钥匙提前签发。这与 anet 的 KEL 预轮换同构。[建议] 发布身份本身可以是一个 anet AID，`anet update` 可直接用 KEL 验证；install.sh 仍用 ssh 格式的公钥。

### 10.4 构建来源与可复现
