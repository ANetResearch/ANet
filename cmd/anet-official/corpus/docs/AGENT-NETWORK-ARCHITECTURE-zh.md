# 智能体网络参考架构与 ANet 实现对照

> 这是一份设计说明，不是规范。它把立场论文《Agent Network for Open Multi-Agent Collaboration with
> Shared Cognition》（张兰、刘云浩，《清华大学学报（自然科学英文版）》2026 年第 31 卷第 6 期，
> 开放获取）提出的参考架构，逐层对到 ANet 与 ANetCore 今天的代码上：哪些已经落地，哪些只有
> 数据结构还没接线，哪些还没有。本文不改任何线协与签名对象；文中“建议”一节的每一条，按
> 贡献指南，凡涉及线协的都要先开议题讨论。
>
> 代码状态以 ANet 0.3.9、ANetCore v0.16.2 为准。与文档站有出入时，以文档站为准。

---

## 一、论文的核心主张，三句话

1. **双窄腰。** 开放的智能体网络需要两个小而稳定的公共抽象：一个管“找得到、够得着”，
   叫智能体定位协议（ALP），以 `agent://<名字>` 为唯一定位原语；一个管“要做什么、做成
   什么算数”，叫任务语义中间表示（TSIR）。两腰之间、之上、之下的东西都可以各自演进，
   但不能替代这两个腰。
2. **四层，加两个接口。** 第一层 ALP（连接腰）；第二层命名与会话，含可靠会话 AXP、
   名字到定位符的解析 ANRP、能力自述 ADP；第三层协作运行时，以共享认知协议 ASCP 为核心；
   第四层 TSIR（语义腰）。往下是“底座服务接口”（字节、流、对端、多地址、主题五个原语），
   往上是“应用服务接口”，入口原语是“编译任务文档、得到运行实例”。
3. **静态语义与运行机制分开，耦合按需升级。** 任务是什么，归 TSIR，可签名、可内容寻址、
   可复用；任务怎么推进，归 ASCP，有状态、有时序。协作耦合从弱到强有四档参考模式：
   痕迹共享、意图对齐、角色绑定、复合体；原则是“先用能保住语义、责任和进度的最弱一档，
   出现局部解决不了的协调缺口再升级”。

另有三条贯穿全栈的原则：身份根在下、签名在上；渐进暴露（传感器只实现第一层，边缘节点
加第二层，完整智能体实现到第四层）；复用而不替代（承诺、证据、结算是可选的领域扩展，
不进必选栈）。

## 二、逐层对照

### 2.1 身份根：已落地，而且是全栈共用的

| 论文 | ANet / ANetCore 现状 |
| --- | --- |
| 身份首先是密钥控制的事实，其次才是协议层身份对象 | 自证明身份：AID 由密钥事件日志（KEL，含预轮换）推导，`identity` 包只接受日志的延伸，回退与分叉一律拒收 |
| 上层所有对象都能对同一个身份根验证 | 统一签名信封 `aobj`：任务文档、委派载荷、回执、评价、黑板单元、A2A 卡片都对同一份 KEL 验签，并且按消息时刻判定密钥是否已被轮换 |

这一层与论文的“原则四”是一回事，没有差距。值得记下的一点：论文把类 DID 的身份对象放在
第二层“描述与发布”，ANet 里对应的是注册到 hub 的 KEL 与签名卡片，hub 只转存、不签发。

### 2.2 第一层 ALP：功能在，名字和形态不同

| 论文 | 现状 | 差距 |
| --- | --- | --- |
| `agent://<名字>` 是唯一定位原语 | 网络上实际用来寻址的是 AID；ANetCore 的 `agenturi` 包已经实现了 `agent://` 的解析、规范化与比较，包括 `agent://*/能力?条件` 这种能力查询形式 | `agenturi` 在 ANet 里还没有调用方，定位符还没有走上线 |
| 具名数据报 | 封装信封：先签名后用 HPKE 封给收件人，签名覆盖收件人、类型、交互、消息号、时间与正文；大小按 Padmé 取整 | 基本对应；数据报以 AID 为名，不以定位符为名 |
| 对端标识的可达性语义 | 传输列表：直连优先、hub 兜底；hub 是按 AID 投递的信箱，存储转发，看不到内容 | 对应 |
| 给上层协议的轻量分派 | 收件后按信封类型分派到任务、付款、能力调用、模块 | 对应 |
| 底座服务接口 | `module/transport.go` 的传输抽象；p2p 模块与 hub 中继是两种底座 | 只用到了“字节”和“对端”两个原语，流、多地址、主题尚未抽象出来 |

论文说 ALP 不做名字解析、不做能力匹配、不做身份签发，ANet 的中继层也恰好如此：hub
不存发送方、类型和交互号，只按收件人投递。窄腰在这里是窄的。

### 2.3 第二层命名与会话：三个子协议都有对应物

| 论文 | 现状 |
| --- | --- |
| AXP：可靠会话与流控 | 任务账本里的“交互”就是会话：多轮往来、状态按 A2A 任务模型单调迁移；需要可靠投递的消息先写待发队列，指数退避重试，重启可恢复 |
| ANRP：把名字或能力需求解析成候选定位符 | hub 注册目录：按能力查找、按关键词查找、A2A 目录接口带游标分页；联邦时跨 hub 合并发现结果 |
| ADP：能力自述 | 签名的 A2A 网络卡片（只含公开能力），迁移期并行的 ADP 卡；卡片按高水位防回滚 |

差距主要在 ANRP。论文要的是“谁能做这类事”，返回定位符和候选对端；今天的查询是能力
标识的精确匹配加关键词匹配，返回 AID 列表。论文第 6.3 节列的研究问题（能力描述要多丰富、
通配查询与缓存怎么相处、语义匹配怎么和信任证据一起排序）在这里都还是空白；路线图里的
“全文检索加向量检索的能力发现”是第一步。

### 2.4 第三层 ASCP：载体已经有了，耦合升级还没有

黑板模块就是论文里“类黑板工作区”这种参考载体的实现：

- **认知单元。** 每条贡献是一个签名、内容寻址的单元，类型有主张、证据、结论、意图、撤回；
  大载荷放进内容寻址存储，只把内容标识签进单元。这正是论文说的“签名的主张、证据、异议、
  临时结论”。
- **可同步。** 单元集合是只增不减的“加入优先集合”，用混合逻辑时钟排序；撤回是一条新的
  撤回单元，不是删除，所以过程可审计、可重放。
- **按任务冻结。** 每个任务有阶段机：进行中、已结论、已归档。结论之后不再接受新单元，
  认知被冻结成稳定快照，这是沉淀的前提。
- **不越界。** 黑板单元被标为组织内对象，第一不变量在运行时拦住它进入公共发布路径，
  第二不变量筛掉对外发布内容里的组织机密。

和论文的四档耦合模式对照：

| 模式 | 现状 |
| --- | --- |
| 痕迹共享 | 已支持：各方往同一个任务的黑板上写签名单元即可 |
| 意图对齐 | 部分支持：任务文档是共同把手，多个提供方可以拿同一份签名任务文档各自执行；但“多个智能体凭同一个任务把手进入同一个黑板”还没有接线 |
| 角色绑定 | 未实现：组织模块提供成员凭证链，可以作为角色的身份依据，但没有“策略、执行、核验、反馈”这样的角色对象 |
| 复合体 | 未实现 |

要特别指出的一处：ANetCore 的任务结构里已经有“耦合提示”字段，取值一到四正对应上面
四档，校验也写好了；但守护进程从不读它，也不据它做任何选择。论文第 4.6 节说任务文档可以
带一个可选的耦合提示、运行时可以在出现反复澄清、语义冲突或强反证时升级，今天这条路径
只有数据结构。

### 2.5 沉淀：只有闸门

论文的沉淀是“有预测才保留”：候选条目要写明它预测的未来任务模式、适用条件、会改变哪个
协调决策、预期收益和验证窗口，只有期望信息价值为正才留下；并按原始痕迹、预测候选、
可复用经验、编译默认值分四级。

ANet 里现在有的是沉淀的前置闸门：阶段机保证只有已结论的任务才能被沉淀，已归档是终态。
把已结论任务的单元提炼成模板、给模板附预测、按后续任务的实际收益升降级，这些都不在本仓。
模块对外也只开放了写入、快照、结论三项能力，归档没有对外入口。

### 2.6 第四层 TSIR：语义腰已经是签名对象

| 论文 | 现状 |
| --- | --- |
| 任务文档可签名、内容寻址、可发现、可复用 | `tsir.TaskDoc`：意图、要求（必须、应当、可选）、验收、上下文、正负作用域谓词、耦合提示；用确定性编码，委派时签的就是它 |
| 输入输出契约与成功判据 | 验收条款与谓词（产物存在与大小、测试通过、指标阈值、作用域）；能力调用的结果以“效果记录”回报，五态效果状态，`completed` 不会掩盖未验证的效果 |
| 静态语义与运行状态分开 | 做到了：随机数、要求方承诺等绑定放在上下文里，是签名原像的一部分但不是运行状态；任务状态、对话、付款都在账本里，不写回任务文档 |
| 编译任务文档、得到运行实例 | 没有这个原语。今天是“一份任务文档对应一次委派”，由调用方手工挑选提供方 |

论文第 4.10 节的论证在这里有实证：如果把第三层并进第四层，任务文档就要背可变状态，同一
任务就没有稳定哈希，也就不能“再编译一次同一份任务文档”来重放。ANet 把任务文档的内容
标识和回执、评价互锁，靠的正是这个稳定哈希。

### 2.7 渐进暴露：在构建层面已经实现

论文的渐进暴露说的是节点按能力裁剪协议栈。ANet 的做法是把裁剪变成构建配置：减法标签
（不带黑板、不带组织、不带付款、不带直连等）默认编入、可以去掉，加法标签默认不编入；
持续集成按符号数双向检查。设备一侧，ANetLink 通过本机套接字把设备运行时接成能力提供者，
守护进程只认“提供者、能力、证据”，不认“设备”。

差距在于：论文的渐进暴露是**协议层面**的，一个只实现第一层的传感器也能在同一命名空间里
被定位、被验证；今天最小的 ANet 节点仍然是一个完整的守护进程，传感器要借边缘节点或
ANetLink 才能进网。

### 2.8 可选扩展：承诺、证据、结算

论文把这三样放在必选栈之外，ANet 也是：回执由提供方签名、评价由要求方签名，二者通过
交互号与内容标识互锁，hub 伪造不了一条评分；付款是同任务内的 a2a-x402 流程，三档支出
上限，hub 只作额度托管方并签结算收据。付款模块可以整体裁掉，裁掉后缺席的模块统一回答
“模块不在”。这一层与论文的划分完全一致。

## 三、守住窄腰的几条约束

从上面的对照里，可以提炼出几条今后改代码时值得守住的约束：

1. **任务文档不背运行状态。** 进度、对话、黑板内容、付款状态都不写回任务文档；需要关联时，
   用任务文档的内容标识去引用。
2. **中继不长语义。** hub 只按收件人投递封装信封；名字解析、能力匹配放在第二层的目录里，
   不进中继。
3. **黑板是一种载体，不是唯一载体。** 论文明确说黑板只是共享工作记忆的一种参考载体。
   今后若加别的载体，应和黑板并列，经由同一套签名单元与阶段机接入，而不是把黑板改宽。
4. **扩展留在扩展里。** 角色、结算、治理参数都不进必选栈；论文第 4.10 节反对第三个窄腰，
   理由正是它会把领域治理冻结成公共必选面。

## 四、建议的演进方向（供讨论，不是承诺）

下列每一条都按“先最小、后扩展”排序。涉及线协或签名对象的，按贡献指南先开议题。

1. **让耦合提示真正起作用（不改线协）。** 字段已在内核里。第一步只需在守护进程里读出来、
   记进任务账本、在任务视图里显示；第二步在黑板模块里，凭同一任务号把多个提供方接入同一
   黑板，实现“意图对齐”档。
2. **把升级信号记下来（不改线协）。** 论文第 6.4 节问“哪些可观测信号足以支持升级”。黑板上
   已经有可观测量：同一任务下主张与反主张的数量、撤回次数、澄清轮数（对话里的输入请求
   状态）。先把这些作为效果记录里的指标暴露出来，供研究使用，再谈自动升级。
3. **任务文档兼容性的测试夹具。** 论文的“判据一”：两个能力匹配的智能体各自依据同一份
   任务文档规划，计划应当语义兼容。可以在联调夹具里加一类场景：同一任务文档分发给两个
   不同后端，比较效果记录是否同时满足验收谓词。这能把一个理论判据变成可回归的测试。
4. **定位符走上线（要讨论）。** `agenturi` 已在内核里；可以先在命令行和本机 A2A 接口接受
   `agent://` 形式，在本地解析成 AID，再考虑注册目录支持能力查询形式。
5. **沉淀候选对象（要讨论）。** 若要做沉淀，建议候选条目按论文第 4.7.2 节写明五项：未来
   任务模式、适用条件、要改变的协调决策、预期收益、验证窗口；并且条目本身是一个签名、
   内容寻址的静态对象，和任务文档同属第四层，不进黑板。这样“沉淀是否带来了收益”就成了
   可证伪、可审计的问题。

## 五、与研究议程的对接

论文第六节以“网络化意图实现”为中心问题，要求能度量语义保持、协调成本、可问责执行和
故障恢复。ANet 今天已经能提供下面这些可观测量，可以直接作为实验数据来源：

| 研究问题 | ANet 里的可观测量 |
| --- | --- |
| 语义保持 | 回执绑定请求任务文档的内容标识；效果记录对验收谓词逐条给出结果 |
| 协调成本 | 回执覆盖的对话记录（消息数、轮数）；黑板单元数与类型分布 |
| 可问责执行 | 签名回执、签名评价、仅追加且前向哈希链接的证据链，可离线导出给第三方核验 |
| 故障恢复 | 任务状态机的取消、失败、拒绝路径；待发队列的重试与重启恢复 |
| 语义容错 | 尚无直接度量；可从“效果为未验证”的比例和撤回单元入手 |

同一研究计划的实证工作见《ANet Patu-1: The Value of Connection in the Agent Network》
（arXiv:2607.15053）：一组廉价的异构智能体在约 2.6 个时即超过一个强得多的同构模型，
十个智能体的网络在没有被告知的情况下重新发现了自己的协作协议。那项工作度量的是“连接
的价值”，本文列出的可观测量可以把它延伸到“耦合档位的价值”。
